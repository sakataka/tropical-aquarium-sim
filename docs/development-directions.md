# 開発方向性

## 現在の方針

このアプリは育成シミュレーションではなく、「リアルな熱帯魚を選び、自分の水景を組み、静かに眺める」鑑賞・コレクション型アクアリウムとして育てます。

起動するとフィッシュルームが表示され、水槽を選んで寄ると水槽画面へ入ります。水槽はサイズ・水景・入れられる魚種が決まった型で、詳細は [複数水槽とフィッシュルーム 設計](multi-tank-design.md) にまとめています。

主役は常に水槽です。操作は魚、水景、照明と音の3領域に留め、愛称、空腹、餌やり、お気に入り、観察文、設置日数、タップ反応など、世話や個体管理を要求する要素は追加しません。

## 2026年9月の基盤

- 16魚種のカタログ情報を各 `species.json` に統合し、フォルダ単位で自動読込
- 魚を個体データではなく魚種別匹数として保存
- 明るい水草景、自然な流木景、根張り流木景、開けた岩組景の4つの一枚絵水景
- 同じ一枚絵から切り抜いた前景レイヤーで、奥の魚が手前の水草の後ろへ回り込む合成
- 水景ごとの構造物位置を魚の受動的な遊泳目標として使用
- 魚の写真1枚をメッシュ変形し、尾の振り・方向転換・上下の傾きを表現
- 出典つきの生態プロファイル（`ecology`）から、泳ぎ方・群れ方・活動時間帯・空気呼吸・底で休む・隠れる・ついばむ・追いかけるを魚種ごとに決める
- 水の揺らぎ、コースティクス、光の筋、照明の色調を1パスで重ねる水中フィルター
- エアストーンから柱状に上がる泡、漂う微粒子、ゆっくり漂うカメラ
- 水槽ごとに決めた魚種と、魚種別・水槽全体の匹数上限
- 保存形式v5（水槽ごと）とv1〜v4移行
- 手動照明、環境音、観賞モード
- 1440×960pxと420×912pxのBun.WebView検証

## 2026年10月の地形・水景拡張

5水槽・30魚種・13水景で、生成背景の画像上のXYと前後位置を持つ経路、遮蔽、障害物、隠れ場所を `scene.json` に定義しています。エビの砂底・石・流木での表面移動に加え、魚の地形回避、葉や岩への採餌、砂での休止、物陰での昼間の休止と夜の離脱を実装しました。背景画像をマスクで重ねるため、追加の立体モデルは不要です。[全水槽への展開](terrain-all-tanks-2026-10.md)。

さらに全13水景の物体輪郭、口・腹・脚の接地、壁際を含む回り込み、通常の緩やかな前後移動と群れの奥行き、低fps時の方向転換を調整しました。生成時に決まる6項目の個体性格で、速さ・休止・群れの間隔・寄り道にも小さな違いを出します。上限匹数で昼10分・夜10分ずつ泳がせる回帰テストと、WebKitでの画面確認を併用します。[品質改善の内容](terrain-quality-2026-10.md)。

## 2026年10月の第2の部屋の見直し

第2の部屋の2水景が、超横長のガラスへ3:2の画像を下端合わせで敷いていたため砂底しか映らなかった問題を、水景ごとの `framing.plateBottom` で直しました。地形は前の水景の複製だったため、画像に合わせて作り直しています。部屋の定義はJSONに寄せ、新しい習性 `homeShelter`、別種どうしの間合い、昼行性の魚の夜の沈み込みを加えました。[見直しの内容](review-2026-10-03-second-room.md)。

## 魚・水景・水槽を足すときの手順

コードの分岐を増やさず、`src/content/` にファイルを置いて足します。`bun run test` の `content.test.ts` が参照切れや置き忘れを検出します。

1. 魚種: `fish/<id>/species.json`・`side.png`・`body.webp`。入れる水槽の `tank.json` の `species` に足す（どの水槽にも入らない魚種はテストで失敗する）。住みかを持つ魚は `homeShelter` の `kind` を決め、その水槽の全水景に同じ `kind` の shelter を置く。
2. 水景: `environment/scenes/<id>/scene.json`・`plate.webp`。地形は画像の輪郭に合わせて書き、使い回さない。水槽のガラスの縦横比が画像よりかなり横長なら `framing.plateBottom` を決め、テストの「画面と同じ切り取り方」でガラス内に収まることを確かめる。
3. 水槽: `tanks/<id>/tank.json`。部屋のJSONの `tanks` にガラス位置を足し、部屋の絵を描き直す（どの部屋にもない水槽はテストで失敗する）。
4. 部屋: `room/<name>.json` と一枚絵。`id`・`order`・`displayName`・`shortName`・`image` を書く。切り替えボタンと部屋の読み込みは自動で増える。
5. `bun run test`・`bun run build`・`bun run verify:webview` で確認し、生成画像は前後関係と420px幅をスクリーンショットで目視する。

## 次に伸ばす方向

### 魚屋カタログ

追加する魚は、既存の写実寄り2D表現、カメラ方向、光、水中感を揃えます。`species.json` と透明背景の `side.png` を1フォルダに置く構造を維持し、中央集約ファイルや魚種別分岐を増やしません。

新しい魚種は次の順で追加します。

1. 公開資料（Seriously Fish、論文、図鑑など）で泳層、群れ方、活動時間帯、特徴的な行動を調べる
2. `ecology` を実在の単位で書き、`sources` に出典を残す。既存の `habits` で表せない行動は、行動の種類として `simulation.ts` に追加してから使う
3. 既存の魚画像をスタイル参照にして `side.png` を画像生成し、`uv run scripts/build-fish-sprites.py` で描画用の `body.webp` を作る
4. `bun run test` と `bun run verify:webview` で確認する

種類を増やす際は、どの水槽に入れるか（既存の水槽に足すか、新しい型の水槽を作るか）を先に決め、泳層の偏り、画像の遅延読込、上限匹数での視認性を確認します。価格、通貨、購入シミュレーション、育成条件は対象外です。

### 水景カタログ

水景は背景・水草・流木・石を別々に生成して組み立てず、完成した一枚絵として画像生成します。部品ごとに光や影、霞み方がずれて作り物に見えるためです。新しい水景は既存の `plate.webp` をスタイル参照にし、同じカメラ位置、水面、光の方向、空気遠近法を揃え、中央から上に魚が泳ぐ余白を残します。

前景レイヤーは同じ一枚絵から物体の輪郭に沿って切り抜きます。枝の間、砂の道、開いた水中を遮蔽に含めず、面ごとの奥行きで魚との前後関係を決めます。自由配置やスロット編集は戻しません。

### 自然な鑑賞体験

遊泳は、境界回避、泳層、群泳、キック・惰性・停止、構造物への緩い接近を少数の説明可能なパラメーターで調整します。見た目の泳ぎは泳ぎフレーム画像を増やさず、`side.png` のメッシュ変形と `swim` パラメーターで調整します。世話への反応、タップ反応、失敗条件は戻しません。

音と照明は手動で、操作しなくても成立する静かな補助に留めます。自動時刻照明と一時停止は当面の対象外です。

### 表示品質と配信サイズ

初回は現在の水景だけで水槽を成立させ、未使用の水景やカタログ下部の画像は必要になるまで読み込みません。アセット追加時は透過品質とともにPNG/WebP/AVIFの適性、PixiJSのテクスチャ使用量、モバイルでの初回表示を測定します。

### 第2のフィッシュルーム（2水槽の試作）

既存5水槽を残し、第2の部屋「海と古代魚」にサンゴ礁の海水水槽とアフリカの古代魚専用水槽を追加しました。新規魚種は海水3種・古代魚2種です。生成した部屋背景と配置情報を使い、選んだ部屋の水槽だけを読み込み・描画します。水槽の左右巡回は同じ部屋内で完結し、最後に開いた水槽から部屋も復元します。保存キーと既存水槽IDは維持します。[試作の構成・出典・素材](second-room-2026-10.md)。

将来は第2の部屋の水槽を5種類程度へ増やす方針ですが、今回はこの2台までを対象とします。次の水槽は、この試作の見た目・泳ぎ・420×912pxでの移動を確認してから選びます。

## 検証方針

coreはVitest、画面は `bun run verify:webview` のBun.WebViewで検証します。Chrome/Chromium headlessは使いません。

変更時は検索・絞り込み・匹数上限・水景・v5復元とv4移行・照明・環境音・観賞モードを確認し、生成画像を変更した場合は水景ごとの前景切り抜きの境界、魚との前後関係、視認性、420px幅の横溢れをスクリーンショットで目視します。
