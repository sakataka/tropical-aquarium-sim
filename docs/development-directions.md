# 開発方向性

このアプリの「今の決まり」をまとめる。これからの進め方は [ロードマップ](roadmap.md)、展示館とアーキテクチャの設計は [水の生き物館 設計](museum-architecture.md)、これまでの経緯は末尾の [経緯](#経緯) にある。

## 体験の方針

このアプリは育成シミュレーションではなく、「リアルな水の生き物を選び、水景を組み、静かに眺め、生態を知る」鑑賞型のアクアリウムとして育てる。

- **舞台は架空の展示館「水の生き物館」（仮称）**（2026年10月に方針を変更。以前は自宅のフィッシュルーム）。生き物を数百種まで増やし、冷たい水、深海、魚以外の水の生き物まで広げても、場所の設定で無理なく説明できるようにするため。館内図（縦の断面図）→ 階 → 展示室 → 水槽の順にたどる。
- **場所は架空でよいが、生き物と水槽の中はリアルに作る。** 載せるのは実在の生き物だけ。深海の生き物や、家庭では飼えない生き物は載せる。架空の生き物は載せない。絶滅種の復元は当面載せない。
- **利用者は館長。** 展示を眺め、水槽ごとに生き物の種類と匹数、水景、照明を組む。水槽はサイズ・水景・入れられる生き物が決まった型で、どの生き物をどの水槽にも入れられる自由は持たせない（[複数水槽の設計](multi-tank-design.md)）。
- **主役は常に水槽。** 操作は生き物、水景、照明と音の3領域に留める。愛称、空腹、餌やり、お気に入り、設置日数など、世話や個体管理を求める要素は足さない。価格、通貨、購入、育成条件も扱わない。
- **図鑑で生態を学べるようにする**（2026年10月に方針を変更。以前は観察文も足さない対象だった）。分類・分布・生息環境・保全状況・この展示で見られる行動を、出典に基づいて解説する。見つけた種を集める、未発見を隠すといった収集や達成の仕組みは付けず、最初から全種を読めるようにする。
- **ガラスを叩いたときの驚きだけは加える**（2026年10月に方針を変更）。実際の水槽で誰もが見る反応で、世話や成績ではないため。近くの魚が逃げ、住みかを持つ魚は住みかへ、物陰に隠れる魚は物陰へ飛び込み、エビは後ろへ跳ねる。続けて叩くと慣れて反応が弱まる。好き嫌いや記憶、得点や罰は付けない。
- 音と照明は手動で、操作しなくても成立する静かな補助に留める。自動時刻照明と一時停止は当面扱わない。

## 生き物の決まり

- 見た目は既存と同じ写実寄りの2D表現にそろえ、カメラの向き、光、水中感、描き込みの密度、透明背景の扱いを合わせる。画像はすべて画像生成で作り、簡易図形やコード生成で代用しない（`AGENTS.md`）。
- 1種につき `src/content/fish/<id>/` の1フォルダに、`species.json`、配信用の `body.webp` を置く。中央の一覧ファイルや、種名での分岐は作らない。原画（`side.png`）は [保管庫](asset-vault.md) へ移していく。
- 生態（`ecology`）は公開資料（Seriously Fish、論文、図鑑など）で泳層、群れ方、活動時間帯、特徴的な行動を調べて書き、`sources` に出典を残す。速度や頻度は実測値ではなく、鑑賞用の調整値。今の `habits` で表せない行動は、行動の種類として core に足してから使う。
- 動きは、体のつくり（`swim.bodyPlan`）の性質と、習性、生態の値から決める。種名で動きを分けない。魚以外の生き物は、体のつくりを足して表す（[体のつくり](museum-architecture.md#3-体のつくり実装済み)）。
- 泳ぎは泳ぎフレームの画像を増やさず、横向きの画像1枚のメッシュ変形と `swim` の値で表す。
- 新しい種を足すときは、どの水槽に入れるか（既存の水槽か、新しい型の水槽か）を先に決め、泳層の偏り、上限匹数での見やすさを確かめる。

## 水景・展示室の決まり

- 水景は背景・水草・流木・石を別々に生成して組み立てず、完成した一枚絵として生成する。部品ごとに光や影、霞み方がずれて作り物に見えるため。既存の `plate.webp` をスタイル参照にし、同じカメラ位置、水面、光の方向、空気遠近法をそろえ、中央から上に魚が泳ぐ余白を残す。
- 地形（経路、遮蔽、障害物、隠れ場所）は `scene.json` に背景画像に対する比率で書く。画像の輪郭に合わせて水景ごとに作り、使い回さない。遮蔽は同じ一枚絵の該当部分をマスクで重ねて作り、自由配置やスロット編集は戻さない。
- 展示室は一枚絵に水槽を5〜6台まで並べる。それを超える場合は展示室を分ける。

## 表示品質と配信サイズ

最初は今の水景だけで水槽を成立させ、未使用の水景や、表示していない展示室の画像は必要になるまで読み込まない。アセットを足すときは、透過の品質とともにPNG/WebP/AVIFの向き不向き、PixiJSのテクスチャ使用量、モバイルでの初回表示を測る。数百種に増えたときの読み込み方は [設計](museum-architecture.md#数百種に耐えるための決まり) にある。

## 魚・水景・水槽・展示室を足すときの手順

コードの分岐を増やさず、`src/content/` にファイルを置いて足す。`bun run test` の `content.test.ts` が参照切れや置き忘れを検出する。

1. 生き物: `fish/<id>/species.json`・`body.webp`（原画 `side.png` から `uv run scripts/build-fish-sprites.py` で作る）。入れる水槽の `tank.json` の `species` に足す（どの水槽にも入らない種はテストで失敗する）。住みかを持つ魚は `homeShelter` の `kind` を決め、その水槽の全水景に同じ `kind` の shelter を置く。魚以外なら `swim.bodyPlan` を指定する（新しい体のつくりが必要なら、先に core と描画の両方に足す）。
2. 水景: `environment/scenes/<id>/scene.json`・`plate.webp`・`thumb.webp`（館内図の縮小版用。`uv run scripts/build-scene-thumbs.py` で作る）。地形・寄り道先・泡の位置はすべて背景画像に対する比率で、画像の輪郭に合わせて書く。水槽のガラスの縦横比が画像よりかなり横長なら `framing.plateBottom` を決め、テストの「画面と同じ切り取り方」でガラス内に収まることを確かめる。
3. 水槽: `tanks/<id>/tank.json`。展示室のJSONの `tanks` にガラス位置を足し、展示室の絵を描き直す（どの展示室にもない水槽はテストで失敗する）。
4. 展示室: `room/<name>.json` と一枚絵。`id`・`order`・`floorId`・`displayName`・`shortName`・`image` を書く。`floorId` は `museum/museum.json` の階のどれか（ない階はテストで失敗する）。館内図のカードと展示室の読み込みは自動で増える。新しい階は `museum.json` の `floors` に足し、館内図の断面図の絵の中の範囲を `mapArea` に書く（絵に階を描き足す必要があれば絵を作り直す）。
5. `bun run test`・`bun run build`・`bun run verify:webview` で確かめ、生成画像は前後関係と420px幅をスクリーンショットで目視する。

## 検証方針

coreはVitest、画面は `bun run verify:webview` の Bun.WebView（WebKit）で検証する。Chrome/Chromium headless は使わない。

変更時は、館内図と展示室の行き来、URLと戻る・進む、生き物の匹数上限、水景、保存の復元と旧形式からの移行、照明、環境音、観賞モードを確かめる。生成画像を変えたときは、遮蔽の境界、魚との前後関係、見やすさ、420px幅での横あふれをスクリーンショットで目視する。
