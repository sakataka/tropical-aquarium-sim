# カニの脚の動き：調査と修正の記録

2026年10月11日。Codexによる調査・実装と、Claude Codeの読み取り専用レビューをまとめます。
修正commitは [4eea1f9](https://github.com/sakataka/tropical-aquarium-sim/commit/4eea1f92896a2bbb9ed4d904bc783f5437da176d) です。
修正前のコードは `9d00b00` で確認できます。

## 結論

ユーザーから「カニの脚が速くカクカク動き、実際のカニと違って見える」という指摘がありました。
調べると、カニ共通の描画が、体格に関係なく速い周期で画像の下半分を波打たせていました。
停止と歩行の切り替えにも、姿勢の変化を滑らかにつなぐ処理がありませんでした。

移動速度と体の大きさからゆっくりした脚の周期を求め、既存画像の脚の位置に沿って動かす形に修正しました。
停止・再開・折り返しを補間し、甲が足先の動きに引っ張られないよう接地点を固定しました。
対象は `bodyPlan: crab` の16種です。画像素材、移動速度の設定、移動経路、飼育・図鑑の情報は変更していません。

これはコードと描画の調査です。実際のカニの歩幅や歩行周期を新たに測定した、生物学の調査ではありません。

## 調査で確認した原因

### 脚の周期が体格に合わず、高い値に達していました

修正前の [crab.ts](../../src/render/bodyPlans/crab.ts) は、歩行中の周期を次の式で決めていました。

```ts
Math.min(4.5, 1.8 + speed * 5)
```

`speed` はcm/秒です。体の大きさや歩幅で割らず、この値を固定の式へ入れていました。
0.54cm/秒以上で上限の4.5Hzに達し、歩行扱いになるだけでも約2Hzになります。
種に設定されていた `swim.tailBeatHz: 0.6` は、カニの脚の周期には使われていませんでした。
停止中も、脚の位相は0.4Hzで進めていました。

設定値からの計算例です。個体差・性格・活動の係数を掛ける前の値で、実画面で測った速度ではありません。

| 種 | 脚を広げた幅 | 巡航の設定 | 巡航速度の計算値 | 修正前の脚の周期 |
|---|---:|---:|---:|---:|
| ヤマトオサガニ | 7cm | 体幅の0.08倍/秒 | 0.56cm/秒 | 4.5Hz |
| ズワイガニ | 63cm | 体幅の0.04倍/秒 | 2.52cm/秒 | 4.5Hz |

歩行に伴う甲の上下動の式は脚の位相を2倍していたため、脚が4.5Hzのときは9Hzの上下動を加えていました。

### 停止と歩行で振幅が瞬時に変わっていました

速度0.04cm/秒を境に、脚の横振幅が画像幅の0.2%から1.2%へ、補間なしで6倍になっていました。
旧コードへ同じ時刻・位相のまま0.04と0.0401cm/秒を渡すと、1024×768のメッシュの頂点が最大約17.13px変わることを再現しました。
これは姿勢の不連続を確認する数値実験で、実画面上の移動量を示す値ではありません。

通常の面の移動でも、休止中は速度0、歩行中は巡航速度になるため、停止・再開のたびにこの切り替えが起きます。

### 脚の位置に合わせず、画像を波打たせていました

旧コードは横位置 `u` に `9π` を掛けて位相をずらし、画像の下半分を変形していました。
各脚の付け根や関節を見ていないため、脚以外の部分も揺れ、脚の位置に合わせた拍の割り当てにはなっていませんでした。
脚を持ち上げる式 `max(0, sin(...))` にも、接地・離地で速度が急に変わる箇所がありました。

### 奥へ進む区間では、歩行中でも停止扱いになり得ました

[fishBody.ts](../../src/render/fishBody.ts) が渡す速度は、画面の横・縦の成分から求めた値です。
一方、[surfaceMotion.ts](../../src/core/surfaceMotion.ts) の経路の長さは奥行きも含みます。
奥行き方向へ進む区間では、体は移動していても画面上の速度が小さくなり、旧描画の歩行判定を下回る可能性がありました。

### 画面を重ねた際の二重更新は、通常の速さの原因ではありませんでした

[fishLayer.ts](../../src/render/fishLayer.ts) は、非activeの画面では変形の時間を進めず、`deltaSec: 0` を渡します。
通常の脚の速さについては、二重更新を原因とする根拠はありませんでした。

## 最終的な修正

| 対象 | 修正後の扱い |
|---|---|
| 脚の周期 | 奥行きを含む移動速度を、体幅の0.12倍を目安とする歩幅で割ります。通常の上限は `tailBeatHz × 1.5` と1Hzの小さい方、逃走時は1.8Hzです。 |
| 停止・再開 | 歩行の度合いと周期を補間します。位相だけを凍結せず振幅を小さくし、浮いた足先を元の姿勢へ戻します。 |
| 折り返し | 横歩きの方向を補間します。体の向きと移動方向が異なる場合も扱います。 |
| 脚の変形 | 16種の既存画像を確認し、`swim.legs` に付け根・関節 `knee`・先端・太さ・拍の組を追加しました。関節に沿った範囲を、小さな振幅で動かします。 |
| 接地・離地 | 接地中は後ろへ運び、浮かせている間に前へ戻します。動きの両端を滑らかにつなぎ、隣の脚を半拍ずらします。 |
| 甲の位置 | `footAnchor` の固定点を水景の面の位置に合わせます。動く足先から毎回接地点を取り直しません。 |
| 採餌・警戒 | はさみの採餌周期も遅くし、採餌・警戒の構えへ入るときと戻るときを補間します。 |
| 奥行きの移動 | 面の移動に `speedCmPerSec` を追加しました。移動式を変えず、奥行きを含む速度を描画へ渡します。 |
| スキーマ | カニの画像では足先が付け根より上に写ることを許容します。カニ以外の「足先は付け根より下」という制約は維持しています。 |

同じ計算例では、修正後の周期の目安はヤマトオサガニが約0.67Hz、ズワイガニが約0.33Hzです。
これらの数値は鑑賞用の調整値です。

脚を大きく振る試作では、粗い画像メッシュが折り返して細い脚が裂けて見えました。
そのため最終実装では、通常の横振幅を画像幅の1.2%に抑えています。
脚ごとの影響範囲はキャッシュし、毎フレームの計算量も抑えました。

## Claude Codeのレビューで追加修正した点

Claude Codeへは非対話・plan・履歴なしで読み取り専用の相談を行い、変更は依頼していません。
初回の診断への同意に加え、変更レビューで次の2点が指摘され、修正と回帰テストを追加しました。

1. **採餌後に歩いているのに脚が止まる問題。** `surfaceMotion.grazing` は休止後も残ります。歩行判定はこのフラグではなく `pauseSec` で行うようにしました。
2. **右向きの体で脚の運びが逆になる問題。** 移動方向は画面上の座標ですが、脚の変位は画像を反転する前の座標です。反転の符号を補正し、左右どちら向きでも接地脚を進行と逆へ運ぶようにしました。

## 検証結果

最終実装に対して、全525テスト、typecheck、buildが通過しています。
[crab.test.ts](../../src/render/bodyPlans/crab.test.ts) の10テストでは、次の内容を確かめています。

- 同じ相対速度なら、大きさが違っても同じゆっくりした周期になること。
- 停止・再開で姿勢が跳ばず、足が浮いたまま固まらないこと。
- `deltaSec: 0` で、移動・採餌・警戒の入力が変わっても姿勢が変わらないこと。
- 30fpsと60fpsで、脚のリズムと姿勢がほぼ一致すること。
- 甲を歩行の波で曲げず、接地点も動く足先に引っ張られないこと。
- 奥行きだけの経路と、採餌後の再開でも脚が動くこと。
- 体の向き・移動方向の4通りで、接地中の脚の運びが正しいこと。
- 全16種の40位相を通常・警戒の両方で確認し、メッシュの三角形が反転しないこと。

追加の [schema.test.ts](../../src/core/schema.test.ts) では、カニの上向きの脚を受け付けつつ、両生類の制約を維持することを確かめています。

画面は `Bun.WebView` のWebKitで、カニのいる5展示室を1440×960と420×912で確認しました。
LocalWebへの反映後も、`cold-crabs-180`、`mudflat-120`、`japan-stream-crab-45` の3水槽を両サイズで確認し、描画エラー・横はみ出しがないことを確認しました。
公開後の実ブラウザでも北の海のカニ水槽を確認しました。いずれもミュートで実施しています。

カニ6匹を描く `cold-crabs-180` の、Mac上の420×912での計測結果です。

| 指標 | 結果 |
|---|---:|
| フレーム間隔の平均 | 16.66ms |
| 20msを超えたフレーム | 0% |
| 計算時間 | 0.11ms |
| 体の変形・配置の計算時間 | 0.06ms |
| 通常フレームのCPU時間（中央値） | 0.48ms |

この計測は変更後の状態の確認で、厳密な変更前後の性能比較ではありません。
LocalWeb・Tailscaleの経路確認と、GitHub Pagesの自動公開も成功しています。

## Claude Codeへ引き継ぐときの参照先

基本仕様は [museum-architecture.md](../museum-architecture.md) の「体のつくり」にも反映済みです。
種を取り込み直すときは、アプリ側の `swim.legs` が残るか確認してください。関節の座標は、切り出した画像の幅・高さを0〜1にした値です。
画像を差し替えた場合は、その画像に合わせて脚の位置と `footAnchor` を見直す必要があります。

動作をさらに調整する場合は、周期だけを下げるのではなく、脚の振幅、接地時間、停止・再開の補間も一緒に確認してください。
画像メッシュの制約があるため、足滑りのない厳密な歩行や、実際のカニの歩き方との完全一致を達成したとはしていません。
エビの描画にも旧カニと似た速度の固定式がありますが、今回の対象はカニで、エビは変更していません。

再確認に使った主なコマンドです。

```sh
bun run test:fast src/render/bodyPlans/crab.test.ts src/core/schema.test.ts src/core/surfaceMotion.test.ts
bun run test
bun run build
bun run verify:webview --halls=northern-seas,japan-rivers,japan-brackish,symbiosis,ryukyu-rivers
bun run measure:perf -- --tanks=cold-crabs-180 --no-build
```

比較画面、スクリーンショット、計測の一時成果物は `tmp/` に置き、Gitには入れていません。
このレポートには、コード・テストの参照と結果を残しています。
