# 水の生き物館（仮称） 設計（2026年10月）

自宅のフィッシュルームから、架空の展示館へ舞台を移す。生き物の種類を数百まで増やしても、世界観と構造が破綻しないようにするための方針と、アーキテクチャの変更点をまとめる。

## なぜ展示館にするか

自宅に置ける水槽は10台程度が限度で、それを超えるとリアリティがなくなる。今後は冷たい水の魚、深海の生き物、カニなど魚以外の水の生き物まで広げたいので、「なぜここにいるのか」を場所の設定で説明できる展示館にする。

- 場所は架空でよい。生き物と水槽の中は、これまでどおりリアルに作る。
- 今の「一枚絵の部屋に5〜6水槽、寄ると水槽画面」という仕組みを、そのまま**展示室**として使う。部屋の上に**館マップ**を1段足す。
- 利用者は**館長**として、展示を眺め、水槽ごとの生き物の数・水景・照明を組む。今の設定操作をそのまま残す。
- 画面の調子はすでに「夜の自然史博物館の展示」を軸にしているので、展示館という設定と合う。

## 載せる生き物の範囲

| 対象 | 方針 |
|---|---|
| 家庭で飼育される魚・エビ | 今の路線 |
| 実在するが家庭では飼えない生き物（深海、冷たい海、大型種、公共水族館でしか見られない種） | 載せる |
| 魚以外の水の生き物（カニ、ヤドカリ、貝、ウニ、クラゲ、タコ、両生類など） | 載せる。体のつくりごとに動きと描画を足す |
| 絶滅種の復元 | 当面は載せない |
| 架空の生き物 | 載せない（世界観が崩れるため） |

「家庭で飼えるかどうか」は図鑑で区別して表示する（下記 `profile.keeping`）。

## 体験の構成

```
館マップ（トップ）   縦の断面図。下へ進むほど深く、遠い水になる
 └ 階（ゾーン）       ジャンルのまとまり。1階に展示室が1つ以上
    └ 展示室           一枚絵に5〜6水槽。今の「部屋」
       └ 水槽          鑑賞モードと設定モード（今と同じ）
図鑑                  全生き物の生態解説。どの水槽で見られるかから水槽へ飛べる
```

### 階の構成案

並びは仮のもので、生き物が増えるにつれて見直す。既存の7水槽はすべてどこかの階に入る。

| 階 | テーマ | 既存の水槽 | 今後の候補 |
|---|---|---|---|
| 地上 | 身近な水辺 | 日本の湧水、小型魚キューブ | 田んぼと小川、渓流 |
| 地下1階 | 熱帯の川と湖 | アマゾン、東南アジア、マラウイ湖 | タンガニイカ湖、マングローブの汽水 |
| 地下2階 | 冷たい水 | — | 北の海（ダンゴウオ、クリオネ、ミズダコ）、ケルプの森 |
| 地下3階 | サンゴ礁と海 | サンゴ礁 | タツノオトシゴ、チンアナゴの砂地、ヤドカリと磯 |
| 地下4階 | 生きた化石 | アフリカの古代魚 | ハイギョ、ガー、チョウザメ、カブトガニ、オウムガイ |
| 地下5階 | 洞窟と深海 | — | 洞窟の盲目魚、ホライモリ、メンダコ、ダイオウグソクムシ、発光する深海魚 |

### 図鑑

生態を学べる内容にする（2026年10月に方針を変更。以前は「観察文などは足さない」としていた）。ただし、見つけた種を集める、未発見を隠す、といった収集・達成の仕組みは付けず、最初から全種を読めるようにする。世話や成績を持ち込まない方針は変えない。

## アーキテクチャの変更点

今の「`src/content/` にフォルダを置けば読み込まれ、zod で形を検証し、`content.test.ts` で参照切れを検出する」という仕組みは、数百種でもそのまま使う。変えるのは次の6点。

### 1. 館・階・展示室の階層

- `src/content/museum/museum.json`: 館の名前、階の一覧（`id`・`order`・名前・テーマ）、断面図の一枚絵と、絵の中で各展示室を指す範囲。
- `room/*.json`（展示室）に `floorId` を足す。ファイル名と既存の部屋ID（`freshwater`・`special`）は変えない。どの階にも属さない展示室はテストで失敗させる。
- 展示室の絵は、展示館の内装で描き直す（暗めの展示室、解説パネル、階ごとに違う内装の色）。ガラスの位置も測り直す。
- 1つの展示室で同時に動かす水槽は6台までとする。それを超える場合は展示室を分ける（iPhone で全水槽を同時に描くため）。

### 2. 画面遷移をURLで持つ

`?tank=` と `?theme=` は今後も使えるようにしたうえで、`?hall=` を足した（図鑑を作るときに `?zukan=<species-id>` を足す）。館内図はクエリなしで、何も指定せずに開くと館内図から始まる。History API で戻る・進むが効き、隣の水槽への移動は履歴を増やさない。GitHub Pages で動くよう、パスではなくクエリで表す。館内図は全階を1画面に並べるので、階を指定するクエリは持たない。

### 3. 体のつくり（`bodyPlan`）を差し替えられる部品にする

今は `swim.bodyPlan` が `"fish" | "crustacean"` の2種類で、`=== "crustacean"` の分岐が simulation・startle・scale・fishPopulation・fishBody など6ファイルに散らばっている。このまま種類を足すと分岐が増え続けるので、先に整理する。

- 体のつくりごとに、初期配置・動き（目標の決め方、速度、驚いたときの反応）・大きさの測り方・描画（メッシュ変形）を1つのモジュールにまとめ、表に登録する。共通の処理は体のつくりの名前で分岐せず、その表を引く。
- 最初に今の `fish` と `crustacean` をこの形へ移す（見た目は変えない）。そのあとで種類を足す。
- 足す候補: `crab`（横歩き。`crustacean` の歩行を流用）、`jelly`（拍動して漂う。尾がない）、`cephalopod`（タコ。腕のうねりと擬態の休止）、`ray`（エイ。ひれの波打ち）、`upright`（タツノオトシゴ。立ったまま背びれで進む）、`burrower`（チンアナゴ。砂から出入りする）、`walker`（両生類。4本脚で歩く）。
- 魚種名で分岐しない、という今の決まりはそのまま守る。

### 4. 水の種類をデータで決める

冷たい水、深海、洞窟、汽水、陸と水があるパルダリウムでは、水中フィルターの色、光の筋、コースティクス、浮遊物、水面の見え方が違う。これをコードの分岐ではなく、`scene.json` の `water` に持つ（水温帯、透明度、光の届き方、浮遊物の量、発光の有無など）。照明の選択肢も水の種類に合わせて変えられるようにする（深海では自然光を出さない、など）。

### 5. 図鑑のデータ

`species.json` の `catalog`（学名、原産地、性質、動き、生息環境）を土台に、`profile` を足す。

- 分類（目・科）、成体の大きさ、分布、生息環境の水温と水質
- `keeping`: 家庭で飼育される / 公共水族館で展示される / 展示例がほとんどない（深海など）
- 保全状況（IUCN レッドリストの区分。出典つき）
- 見どころ（この展示で観察できる行動。`ecology.habits` と対応させる）
- 出典は今の `ecology.sources` と共通にする

文章は公開資料に基づき、出典のない数値は書かない。

### 6. アセットの保管庫と制作キュー

数百種の画像を外部のエージェントに夜間などにまとめて作らせ、手元で確認して取り込めるようにする。原画（`side.png` など）はリポジトリの外の**保管庫**に置き、リポジトリには配信用の `body.webp` と `plate.webp` だけを入れる。今の `side.png` は合計55MBあり、数百種では数百MBになるため。

保管庫の実体（同期フォルダ、別のGitHubリポジトリ、クラウドストレージ）は、外部エージェントが書き込める先に合わせて後で決める。手元のスクリプトは環境変数 `AQUARIUM_ASSET_VAULT` で保管庫のパスを受け取り、実体に依存しない。

```
<保管庫>/
  requests/<種類>/<id>.json        制作依頼（下記）
  species/<species-id>/
    side.png                       採用した原画
    candidates/<日時>-<n>.png      候補（外部エージェントが置く）
    research.json                  生態・図鑑の下書きと出典（任意）
    meta.json                      状態、生成日時、使った指示文、参照画像
  scenes/<scene-id>/plate.png ...  水景の原画と候補
  halls/<room-id>/ ...             展示室の原画と候補
  museum/ ...                      館マップの原画と候補
```

- 制作依頼には、対象の和名・学名、用途（魚の横向き、水景、展示室など）、縦横比、透過の要否、頭の向き、スタイル参照にする既存画像、世界観の注意点（`AGENTS.md` のアセット制作方針）を書く。依頼ファイルを作るスクリプトを用意し、毎回同じ書式にする。
- 状態は `meta.json` の `status` で `requested → generated → accepted / rejected → installed` と進める。
- 取り込みスクリプトが、透過、頭の向き、解像度、余白、体の外接矩形を検査してから `body.webp` を作り、`src/content/` に置く（今の `install-fish-sprite.py` と `build-fish-sprites.py` を保管庫に対応させる）。採用の判断は手元で行い、生成物を自動では取り込まない。
- 生態の調査（`ecology`・`catalog`・`profile` の下書き）も同じ依頼に含められる。取り込む前に出典を確認する。
- 既存の `side.png` を保管庫へ移しても、Gitの履歴にある分は残る。履歴の書き換えは行わない。

### 数百種に耐えるための決まり

- 魚種・水槽・展示室の追加は、これまでどおりファイルを置くだけで済み、中央の一覧ファイルを編集しない。
- 画像は表示中の展示室の分だけ読み込む（今の方針を維持）。
- 魚種のJSONは今は全部を最初に読む（35種で約75KB）。100種を超えたら、図鑑の一覧と検索に使う軽い索引だけを最初に読み、生態などの詳細は展示室や図鑑の項目を開いたときに読む形へ分ける。読み込み関数は、その時に呼び出し側を書き換えずに済むよう非同期の形にそろえておく。
- `content.test.ts` の検査（参照切れ、画像の有無、地形がガラス内に収まるか）は種数に比例して増えるので、遅くなったら並列化する。

## 進める順番

1. この設計と方針の文書化（このファイル）
2. 館・階・展示室の階層、館マップ（最初は簡素な断面図）、URL遷移。今の2部屋をそのまま展示室として入れる（2026年10月に実装。館内図はHTMLの断面図で、絵は手順4で作る。今の2部屋は地上と地下2階に仮に置き、古代魚の水槽は展示室を描き直すときに地下3階へ移す）
3. 保管庫と制作キュー: 依頼ファイルの書式、依頼を作るスクリプト、取り込み・検査スクリプト。既存の原画を保管庫へ移す
4. 展示室の絵と館マップの絵を、展示館の内装で生成し直す
5. `bodyPlan` の整理（`fish`・`crustacean` を部品化。見た目は変えない）と、最初の魚以外の生き物（カニかクラゲ）
6. 水の種類（`water`）と、冷たい水の展示室
7. 図鑑（`profile` の追加と画面）
8. 以降は生き物と展示室を増やしながら、必要になった時点で魚種データの遅延読み込みへ移る
