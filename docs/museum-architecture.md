# 水の生き物館（仮称） 設計（2026年10月）

自宅のフィッシュルームから、架空の展示館へ舞台を移す。生き物の種類を数百まで増やしても、世界観と構造が破綻しないようにするための方針と、アーキテクチャの変更点をまとめる。

## なぜ展示館にするか

自宅に置ける水槽は10台程度が限度で、それを超えるとリアリティがなくなる。今後は冷たい水の魚、深海の生き物、カニなど魚以外の水の生き物まで広げたいので、「なぜここにいるのか」を場所の設定で説明できる展示館にする。

- 場所は架空でよい。生き物と水槽の中は、これまでどおりリアルに作る。
- 今の「一枚絵の部屋に5〜6水槽、寄ると水槽画面」という仕組みを、そのまま**展示室**として使う。部屋の上に**館マップ**を1段足す。
- 利用者は**館長**として、展示を眺め、水槽ごとの生き物の数・水景・照明を組む。今の設定操作をそのまま残す。
- 画面の調子はすでに「夜の自然史博物館の展示」を軸にしているので、展示館という設定と合う。

## 載せる生き物の範囲

| 対象 | 方針 |
|---|---|
| 家庭で飼育される魚・エビ | 今の路線 |
| 実在するが家庭では飼えない生き物（深海、冷たい海、大型種、公共水族館でしか見られない種） | 載せる |
| 魚以外の水の生き物（カニ、ヤドカリ、貝、ウニ、クラゲ、タコ、両生類など） | 載せる。体のつくりごとに動きと描画を足す |
| 絶滅種の復元 | 当面は載せない |
| 架空の生き物 | 載せない（世界観が崩れるため） |

「家庭で飼えるかどうか」は図鑑で区別して表示する（下記 `profile.keeping`）。

## 体験の構成

```
館内図（トップ）     横長の断面図。地上3階に身近な水から海まで、地下1階は特別展示
 └ 階（ゾーン）       ジャンルのまとまり。1階に展示室が1つ以上
    └ 展示室           一枚絵に5〜6水槽。今の「部屋」
       └ 水槽          鑑賞モードと設定モード（今と同じ）
図鑑                  全生き物の生態解説。どの水槽で見られるかから水槽へ飛べる
```

### 階の構成

地上4階・地下2階、17展示室、80水槽にする（2026年10月5日に決定。それまでは地上3階・地下1階の暫定の枠だった）。上へ行くほど遠い水、下へ行くほど特殊な水という並びで、館の紹介文「身近な水辺から、遠く深い水へ」に合わせた。1つの水槽に多くの種を詰めると見栄えが悪くなるので、展示室と水槽の数で種数を受け止める。

| 階 | テーマ | 展示室 |
|---|---|---|
| 4階 | 冷たい水 | 渓流と北の湖、北の海、ケルプの森とクラゲ |
| 3階 | サンゴ礁と海 | サンゴ礁の海、共生と擬態、日本の海 |
| 2階 | 世界の川と湖 | アマゾンの小さな魚、中南米の大河、アフリカの湖と川、アジアとオセアニアの川 |
| 1階 | 日本の水辺 | 日本の川、田んぼとため池、干潟とマングローブ |
| 地下1階 | 生きた化石 | 古代魚の大河、生きている化石 |
| 地下2階 | 洞窟と深海 | 洞窟と深海の底、深海の光 |

水槽ごとの種と水景の説明は、保管庫の `catalog/exhibit-plan.json`（展示計画）が正本。水槽は2段階で開ける。

- 第1弾（64水槽）: 今の描き方（魚とエビの真横の画像）で動く約200種。
- 第2弾（16水槽）: カニ、クラゲ、タコ、エイ、両生類などの体のつくりを足してから。展示室の絵にはガラスだけ先に描いておき、準備中として出す。

今のアプリの `museum.json` は、展示室の絵が届くまで、旧来の地上3階・地下1階の枠のままにしている。新しい館内図と展示室の絵がそろったところで切り替える。

### 図鑑

生態を学べる内容にする（2026年10月に方針を変更。以前は「観察文などは足さない」としていた）。ただし、見つけた種を集める、未発見を隠す、といった収集・達成の仕組みは付けず、最初から全種を読めるようにする。世話や成績を持ち込まない方針は変えない。

## アーキテクチャの変更点

今の「`src/content/` にフォルダを置けば読み込まれ、zod で形を検証し、`content.test.ts` で参照切れを検出する」という仕組みは、数百種でもそのまま使う。変えるのは次の6点。

### 1. 館・階・展示室の階層（実装済み）

- `src/content/museum/museum.json`: 館の名前と、階の一覧（`id`・`order`（上からの並び）・「1階」「地下1階」などの表示・英字名・テーマ）と、各階の展示室の枠（`halls`）。読み込みは `src/core/museum.ts`。
- 展示室をどの階のどこに置くかは `museum.json` の `halls` だけで決める（2026年10月4日に `room/*.json` の `floorId` をやめた）。枠の `id` と同じ `room/*.json` があれば開いている展示室、なければ準備中で、準備中の枠には `displayName` を書く。どの枠にも置かれていない展示室はテストで失敗する。ファイル名と既存の部屋ID（`freshwater`・`special`）は変えていない。
- 館内図（`src/ui/MuseumMap.tsx`）は、画像生成した館の断面図（`src/content/museum/museum-section.webp`）の上に、展示室の枠を重ねる。絵は横長の概念図として抽象度を高くし、特定の生き物・水槽の数や形や部屋の仕切りは描かず、階ごとの水の色と光だけで表す（展示の中身や展示室の数が変わっても絵と矛盾せず、描き直さずに済むように）。各階の範囲は `museum.json` の `floors[].mapArea`（絵の画素）に書き、その階の展示室の枠で左から等分する。絵を差し替えたら測り直す。狭い画面では `map.focus` の範囲（建物と階名の札）だけを切り出して大きく見せる。開いている展示室の枠には、その展示室の画面の縮小版（`src/ui/HallPreview.tsx`）を映す。展示室の絵を水槽の並びのあたりで切り取り、各ガラスに今の水景の小さな画像（`thumb.webp`。館内図では `plate.webp` を読まない）を展示室の画面と同じ置き方（`framePlate`）で重ねるので、水景や展示室の絵を変えても縮小版を作り直す必要はない。魚はこの大きさでは見えないので描かない。準備中の枠は少し暗くして名前と「準備中」を出す。横（狭い画面では下）のフロアガイドと断面図は、どちらかに触れると同じ階・展示室が光る。
- 展示室の絵は、展示館の内装で描き直す（暗めの展示室、解説パネル、階ごとに違う内装の色）。ガラスの位置も測り直す。
- 1つの展示室で同時に動かす水槽は6台までとする。それを超える場合は展示室を分ける（iPhone で全水槽を同時に描くため）。

### 2. 画面遷移をURLで持つ（実装済み）

`?tank=` と `?theme=` は今後も使えるようにしたうえで、`?hall=` を足した（図鑑を作るときに `?zukan=<species-id>` を足す）。館内図はクエリなしで、何も指定せずに開くと館内図から始まる。History API で戻る・進むが効き、隣の水槽への移動は履歴を増やさない。GitHub Pages で動くよう、パスではなくクエリで表す。館内図は全階を1画面に並べるので、階を指定するクエリは持たない。

### 3. 体のつくり（実装済み）

魚以外の生き物を足すための土台。以前は `swim.bodyPlan` の `=== "crustacean"` という分岐が simulation・startle・scale・fishPopulation・fishBody など6ファイルに散らばっていた。2026年10月に、見た目と動きを変えずに次の形へ移した。

- **性質（core）**: `src/core/bodyPlans.ts` の `BODY_PLANS` に、体のつくりごとの性質を書く。シミュレーションは体のつくりの名前ではなく、この性質を見て分岐する。

  | 性質 | 意味 | `fish` | `crustacean`（エビ） |
  |---|---|---|---|
  | `walksOnSurfaces` | 地形のある水景では、泳がずに面の上を歩く | × | ○ |
  | `bottomDweller` | 底で暮らし、泳層や水中の寄り道先へ浮き上がらない | × | ○ |
  | `tailKick` | 尾で蹴って加速する | ○ | × |
  | `antennae` | 画像の前端に触角があり、体長は `swim.headStart` より後ろで測る | × | ○ |
  | `startle` | 叩かれたときの逃げ方 | `dart`（泳ぎ去る） | `tailFlip`（後ろへ跳ねる） |

- **描き方（render）**: `src/render/bodyPlans/` に体のつくりごとのファイルを置き、メッシュの縦の分割数と毎フレームの変形を書く。`index.ts` の `BODY_PLAN_RENDERERS` に登録する。
- core の `BODY_PLANS` に足した体のつくりが描き方の表になければ型エラーになり、`bodyPlans.test.ts` でも検出する。

新しい体のつくりを足す手順:

1. 足す生き物の動きを公開資料で調べ、今の性質で表せるか確かめる。表せない動きは、性質を1つ足し、simulation などで性質を見て分岐する（体のつくりの名前で分岐しない）。
2. `BODY_PLANS` に性質を書く。
3. `src/render/bodyPlans/<id>.ts` に変形を書き、`BODY_PLAN_RENDERERS` に登録する。
4. `species.json` の `swim.bodyPlan` に指定し、テストと画面で確かめる。

足す候補: `crab`（横歩き。エビの歩行を流用）、`jelly`（拍動して漂う。尾がない）、`cephalopod`（タコ。腕のうねりと擬態の休止）、`ray`（エイ。ひれの波打ち）、`upright`（タツノオトシゴ。立ったまま背びれで進む）、`burrower`（チンアナゴ。砂から出入りする）、`walker`（両生類。4本脚で歩く）。

### 4. 水の種類をデータで決める

冷たい水、深海、洞窟、汽水、陸と水があるパルダリウムでは、水中フィルターの色、光の筋、コースティクス、浮遊物、水面の見え方が違う。これをコードの分岐ではなく、`scene.json` の `water` に持つ（水温帯、透明度、光の届き方、浮遊物の量、発光の有無など）。照明の選択肢も水の種類に合わせて変えられるようにする（深海では自然光を出さない、など）。

### 5. 図鑑のデータ

`species.json` の `catalog`（学名、原産地、性質、動き、生息環境）を土台に、`profile` を足す。

- 分類（目・科）、成体の大きさ、分布、生息環境の水温と水質
- `keeping`: 家庭で飼育される / 公共水族館で展示される / 展示例がほとんどない（深海など）
- 保全状況（IUCN レッドリストの区分。出典つき）
- 見どころ（この展示で観察できる行動。`ecology.habits` と対応させる）
- 出典は今の `ecology.sources` と共通にする

文章は公開資料に基づき、出典のない数値は書かない。

### 6. アセットの保管庫と制作キュー

数百種の画像を外部のエージェントに夜間などにまとめて作らせ、手元で確かめて取り込めるようにする。原画はリポジトリの外の保管庫（非公開リポジトリ `sakataka/aquarium-assets`）に置き、このリポジトリには配信用の `body.webp` と `plate.webp` だけを入れる。今の `side.png` は合計55MBあり、数百種では数百MBになるため。フォルダ構成、依頼の書式、状態の進め方、取り込みの手順は [アセットの保管庫](asset-vault.md) にまとめる。

### 数百種に耐えるための決まり（2026年10月5日に実装）

起動時に読むものを、館内図に要るものだけに絞る。展示室の中身は、その展示室に入るときに読む。

| いつ読むか | 中身 |
|---|---|
| 起動時 | `museum.json`、展示室（`room/*.json`）、水槽（`tank.json`）、水景の見出し（`scene.json`。名前、既定の照明、切り取り方）、画像の URL の表 |
| 展示室に入るとき | その展示室の水槽で選べる魚種（`species.json`）と水景の地形（`terrain.json`）。`core/hallContent.ts` の `loadHallContent` がまとめて読み、zod で検証する。読み終わるまでは「展示室を準備しています」を出す |
| 展示室に入るとき | 展示室と水槽の描画（PixiJS を含む）。館内図にいる間に先読みする |
| 展示室を移ったとき | 前の展示室のテクスチャ（部屋の絵、水景、魚）を GPU から外す（`render/assets.ts` の `releaseTexturesExcept`）。館内図にいる間は、直前の展示室の分を残す |

- 魚種の JSON と地形は1件ずつ別のチャンクになる。種や水景をいくら足しても、最初に読む JS は増えない（2026年10月5日時点で、最初に読む JS は426KB、gzip で132KB。以前は786KB、gzip で240KB）。
- 魚の個体は、その展示室の魚種を読んでから生まれる。保存データの検証は魚種の中身を使わず、ID の表（`speciesDirectory`）だけで行う。
- 館内図の縮小版は、部屋の絵の小さな版（`room/thumbs/`、幅960px）と水景の `thumb.webp` だけを読み、画面外のものは遅れて読む。
- 魚種・水槽・展示室の追加は、これまでどおりファイルを置くだけで済み、中央の一覧ファイルを編集しない。
- テストは `src/core/testSetup.ts` で全魚種と全地形を先に読んでから検査する。
