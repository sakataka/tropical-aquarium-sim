# 水の生き物館（仮称） 設計（2026年10月）

自宅のフィッシュルームから、架空の展示館へ舞台を移す。生き物の種類を数百まで増やしても、世界観と構造が破綻しないようにするための方針と、アーキテクチャの変更点をまとめる。

## なぜ展示館にするか

自宅に置ける水槽は10台程度が限度で、それを超えるとリアリティがなくなる。今後は冷たい水の魚、深海の生き物、カニなど魚以外の水の生き物まで広げたいので、「なぜここにいるのか」を場所の設定で説明できる展示館にする。

- 場所は架空でよい。生き物と水槽の中は、これまでどおりリアルに作る。
- 今の「一枚絵の部屋に5〜6水槽、寄ると水槽画面」という仕組みを、そのまま**展示室**として使う。部屋の上に**館マップ**を1段足す。
- 利用者は**館長**として、展示を眺め、水槽ごとの生き物の数・水景・照明を組む。今の設定操作をそのまま残す。
- 画面の調子はすでに「夜の自然史博物館の展示」を軸にしているので、展示館という設定と合う。

## 載せる生き物の範囲

| 対象 | 方針 |
|---|---|---|
| 家庭で飼育される魚・エビ | 今の路線 |
| 実在するが家庭では飼えない生き物（深海、冷たい海、大型種、公共水族館でしか見られない種） | 載せる |
| 魚以外の水の生き物（カニ、ヤドカリ、貝、ウニ、クラゲ、タコ、両生類など） | 載せる。体のつくりごとに動きと描画を足す |
| 絶滅種の復元 | 当面は載せない |
| 架空の生き物 | 載せない（世界観が崩れるため） |

「家庭で飼えるかどうか」は図鑑で区別して表示する（下記 `profile.keeping`）。

## 体験の構成

```
館内図（トップ）     断面図。地上4階に身近な水から海まで、地下2階は特別展示
 └ 階（ゾーン）       ジャンルのまとまり。1階に展示室が1つ以上
    └ 展示室           一枚絵に5〜6水槽。今の「部屋」
       └ 水槽          鑑賞モードと設定モード（今と同じ）
図鑑                  全生き物の生態解説。どの水槽で見られるかから水槽へ飛べる
```

### 階の構成

地上4階・地下2階、18展示室、84水槽にする（2026年10月5日に決定。同日に3階へ「ちいさな生き物」を足した。それまでは地上3階・地下1階の暫定の枠だった）。上へ行くほど遠い水、下へ行くほど特殊な水という並びで、館の紹介文「身近な水辺から、遠く深い水へ」に合わせた。1つの水槽に多くの種を詰めると見栄えが悪くなるので、展示室と水槽の数で種数を受け止める。

| 階 | テーマ | 展示室 |
|---|---|---|
| 4階 | 冷たい水 | 渓流と北の湖、北の海、ケルプの森とクラゲ |
| 3階 | サンゴ礁と海 | サンゴ礁の海、共生と擬態、日本の海、ちいさな生き物（階のテーマをまたいで数cmの生き物を見せる） |
| 2階 | 世界の川と湖 | アマゾンの小さな魚、中南米の大河、アフリカの湖と川、アジアとオセアニアの川 |
| 1階 | 日本の水辺 | 日本の川、田んぼとため池、干潟とマングローブ |
| 地下1階 | 生きた化石 | 古代魚の大河、生きている化石 |
| 地下2階 | 洞窟と深海 | 洞窟と深海の底、深海の光 |

水槽ごとの種と水景の説明は、保管庫の `catalog/exhibit-plan.json`（展示計画）が正本。水槽は2段階で開ける。

- 第1弾（66水槽）: 今の描き方（魚とエビの真横の画像）で動く約200種。
- 第2弾（18水槽）: カニ、クラゲ、タコ、エイ、両生類などの体のつくりを足してから。展示室の絵にはガラスだけ先に描いておき、準備中として出す。

2026年10月6日に、新しい館内図と展示室の絵へ切り替え、18室すべてを開けた。旧来の2部屋（淡水の展示室、海と古代魚の展示室）はなくし、既存の7水槽は新しい展示室へ移した（水槽IDは変えていない）。開けたのは魚とエビ（エビの描き方で歩く甲殻類を含む）だけが入る70水槽・254種で、魚以外の生き物を待つ14水槽（カニ、クラゲ、タコ、タツノオトシゴ、オウムガイ、カブトガニなど）は、展示室の絵のガラスに水景を暗く焼き込んで見せ、まだ入れない。10月8日にカニの体のつくりを足し、カニの2水槽（北の海のカニ、沢のサワガニ）を開けた。同じ日にクラゲの体のつくりを足し、クラゲの3水槽（冷たい海のクラゲ、海のクラゲ、深海のクラゲ）を開けた。準備中は9水槽。

### 図鑑

生態を学べる内容にする（2026年10月に方針を変更。以前は「観察文などは足さない」としていた）。ただし、見つけた種を集める、未発見を隠す、といった収集・達成の仕組みは付けず、最初から全種を読めるようにする。世話や成績を持ち込まない方針は変えない。

## アーキテクチャの変更点

今の「`src/content/` にフォルダを置けば読み込まれ、ビルド時に zod で形と参照を検証し、`content.test.ts` で参照切れを検出する」という仕組みは、数百種でもそのまま使う。変えるのは次の6点。

### 1. 館・階・展示室の階層（実装済み）

- `src/content/museum/museum.json`: 館の名前と、階の一覧（`id`・`order`（上からの並び）・「1階」「地下1階」などの表示・英字名・テーマ）と、各階の展示室の枠（`halls`）。読み込みは `src/core/museum.ts`（ビルド時に作る館の索引 `virtual:museum` を読む）。
- 展示室をどの階のどこに置くかは `museum.json` の `halls` だけで決める（2026年10月4日に `room/*.json` の `floorId` をやめた）。枠の `id` と同じ `room/*.json` があれば開いている展示室、なければ準備中で、準備中の枠には `displayName` を書く。どの枠にも置かれていない展示室はテストで失敗する。ファイル名と既存の部屋ID（`freshwater`・`special`）は変えていない。
- 館内図（`src/ui/MuseumMap.tsx`）は2段（2026年10月7日から）。1段目は、画像生成した館の断面図（`src/content/museum/museum-section.webp`）に階の帯を重ねたものと、横（狭い画面では下）のフロアガイドで、階を選ぶ。2段目は、選んだ階の展示室を縮小版つきのカードで並べ、上に館内図へ戻るボタンと階の切り替えを置く。展示室が約35室に増えても、1段目に並ぶのは階の数だけで、展示室名が帯の中で切れない。前回の展示室があれば、1段目の見出しの下に、そこへ直接戻るボタンを出す。
- 断面図の絵は横長の概念図として抽象度を高くし、特定の生き物・水槽の数や形や部屋の仕切りは描かず、階ごとの水の色と光だけで表す（展示の中身や展示室の数が変わっても絵と矛盾せず、描き直さずに済むように）。各階の範囲は `museum.json` の `floors[].mapArea`（絵の画素）に書く。絵を差し替えたら測り直す。狭い画面では `map.focus` の範囲（建物と階名の札）だけを切り出して大きく見せる。断面図の帯とフロアガイドは、どちらかに触れると同じ階が光り、その階の配置を先読みする。
- 階の一覧の開いている展示室には、その展示室の画面の縮小版（`src/ui/HallPreview.tsx`）を映す。展示室の絵を水槽の並びのあたりで2:1に切り取り、各ガラスに今の水景の小さな画像（`thumb.webp`。館内図では `plate.webp` を読まない）を展示室の画面と同じ置き方（`framePlate`）で重ねるので、水景や展示室の絵を変えても縮小版を作り直す必要はない。魚はこの大きさでは見えないので描かない。準備中の枠は破線のカードで名前と「準備中」を出す。
- 展示室の絵は、展示館の内装で描き直す（暗めの展示室、解説パネル、階ごとに違う内装の色）。ガラスの位置も測り直す。
- 1つの展示室で同時に動かす水槽は6台までとする。それを超える場合は展示室を分ける（iPhone で全水槽を同時に描くため）。

### 2. 画面遷移をURLで持つ（実装済み）

館内図はクエリなし、階の一覧は `?floor=`、展示室は `?hall=`、水槽は `?tank=`（`?theme=` で水景を指定しても開ける）、図鑑は `?zukan` と `?zukan=<種>`。何も指定せずに開くと館内図から始まる。History API で戻る・進むが効き、隣の水槽や隣の階への移動は履歴を増やさない。展示室の「館内図」ボタンと Esc は、その展示室の階の一覧へ戻り、階の一覧の Esc は館内図へ戻る。GitHub Pages で動くよう、パスではなくクエリで表す。

  カニ（2026年10月8日）は、dots の斜め上から見た3/4の画像（前が左）を使う。`realBodyLengthCm` は画像の横幅に当たる実寸（脚を広げた幅の目安）で、図鑑の `adultSizeCm` は甲幅で書く。描き方（`src/render/bodyPlans/crab.ts`）は、左右に広がる脚を隣どうし逆の拍で上げ下ろしし、ついばむときは左右のはさみを交互に口へ運ぶ。

  クラゲ（2026年10月8日）は、dots の真横から見た画像（傘が上）を反転せずに使う。`swim.bell` に画像のうち傘の範囲（上端0〜下端1）を書き、`realBodyLengthCm` は画像の横幅に当たる実寸、図鑑の `adultSizeCm` は傘の直径（クシクラゲは体長）で書く。動き（`src/core/driftMotion.ts`）は、傘を素早く縮めて開く拍（`swim.tailBeatHz`）のうち縮む間だけ傘の向きへ進み、開く間は水の抵抗で減速しながら沈む。行き先が上なら強く、下なら弱く拍動し、行き先の方へ傘を最大24°ほど傾ける。拍の位相 `pulsePhase` と傾き `tilt` は個体が持ち、描き方（`src/render/bodyPlans/jelly.ts`）と共有する。描き方は、傘を縁ほど強くすぼめて背を伸ばし（`swim.tailSweepRad` が縮み具合）、触手と口腕を少し遅れてすぼめながら根元から先へ波打たせる（`swim.waveCount` が波の数）。傘が画像の下にある種（サカサクラゲ）は、底に伏せたまま拍動し、ときどき少し場所を移す。拍動しない種（`tailSweepRad: 0`。カブトクラゲ）は、一定の速さで漂い、体全体をゆっくり揺らす。どのクラゲも群れ・住みか・地形の面を使わず、ほかの個体とは傘が重ならない程度に離れる。

  タコ（2026年10月8日）は、dots の斜め上から見た3/4の画像（目が左、胴が右上、腕を四方へ広げる）を使う。`swim.mouthAnchor` に腕の集まる口の位置、`swim.footAnchor` に底に着く点を書き、`realBodyLengthCm` は画像の横幅（腕を広げた幅）。動きはカニと同じく面を歩く仕組み（`src/core/surfaceMotion.ts`）で、進む向きへ体を向け、`bottomRest` で長く休む。驚くと、胴（画像の右）を先にして面に沿って噴射で飛び退く（種の burst の速さで0.5〜0.8秒）。描き方（`src/render/bodyPlans/octopus.ts`）は、口を中心にした小さな回転で腕を根元から先へうねらせ（隣り合う腕で拍をずらす）、這うときは腕を伸び縮みさせ、胴を呼吸でかすかに膨らませる。噴射では胴をすぼめ、腕を口の高さへそろえて左へなびかせる。

  イカ（2026年10月8日）は、dots の真横の画像（腕が左）を使う。オウムガイ・コウモリダコもこの体のつくりで描く。`swim.headStart` が腕の付け根、`swim.mouthAnchor.y` が体の中心線の高さ、`swim.bodyWaveStart` がひれの始まり（ひれのないオウムガイは1）、`swim.waveCount`・`swim.verticalFlex`・`swim.tailBeatHz` がひれの波の数・振れ幅・拍、`swim.tailSweepRad` が噴射で胴をすぼめる量。動きは魚と同じ仕組みで、向き（facing）だけを `reverses` で決める。驚くと、向きを変えずに叩いた所から離れる（頭の前を叩けば胴を先にして後ろへ）。描き方（`src/render/bodyPlans/squid.ts`）は、胴の上下の縁のひれを後ろへ波打たせ、腕を根元から先へ揺らし、噴射の間は胴をすぼめて腕を中心線へそろえる。後ろへ進むときは胴の側を進む向きへ傾ける。

### 4. 水の種類をデータで決める

冷たい水、深海、洞窟、汽水、陸と水があるパルダリウムでは、水中フィルターの色、光の筋、コースティクス、浮遊物、水面の見え方が違う。これをコードの分岐ではなく、`scene.json` の `water` に持つ（水温帯、透明度、光の届き方、浮遊物の量、発光の有無など）。照明の選択肢も水の種類に合わせて変えられるようにする（深海では自然光を出さない、など）。

**水面の高さ（実装済み）**: 水面の上の空気まで見える水景は、`scene.json` の `waterLine` に水面の高さを持つ（背景画像に対する比率。`front` はガラス側、`back` は奥で水面が見える高さ。奥ほど上に見える）。シミュレーションは `src/core/waterColumn.ts` で奥行きごとの水面の高さを求め、次のように扱う。

- 泳ぐ層（`preferredZone`）の上下は、水槽全体ではなく水の部分に対する比率として当てる。初期配置も同じ比率で水の部分へ置く。
- 魚は水面より上へ泳ぎ出さない。空気呼吸（`airBreathing`）の行き先は水面、驚いて逃げる先も水の中。
- 巣穴など地形の目的地は水の外に置いてもよい（干潟の巣穴）。向かう間は水面で止めず、出たあとは止まらずに水へ戻る。
- 水面のすぐ下まで岩があるところでは岩を優先し、押し上げられた分だけ水面の余白に入ってよい。
- 水中の浮遊物は手前の水面より下にだけ漂わせる。

### 5. 図鑑のデータ

`species.json` の `catalog`（学名、原産地、性質、動き、生息環境）を土台に、`profile` を足す。

- 分類（目・科）、成体の大きさ、分布、生息環境の水温と水質
- `keeping`: 家庭で飼育される / 公共水族館で展示される / 展示例がほとんどない（深海など）
- 保全状況（IUCN レッドリストの区分。出典つき）
- 見どころ（この展示で観察できる行動。`ecology.habits` と対応させる）
- 出典は今の `ecology.sources` と共通にする

文章は公開資料に基づき、出典のない数値は書かない。

**画面（実装済み）**: `src/ui/Zukan.tsx`。全種の一覧（展示順・分類順・名前順、淡水・汽水・海水で絞り込み）、検索（名前、かな、学名、別名、目・科、原産地）、1種ずつの解説、見られる水槽（そこから水槽へ移る）。`?zukan` で一覧、`?zukan=<種>` で解説を、館内図の上に開く。図鑑の中で進んだ数を履歴に持ち、閉じるとその分だけ戻る。収集や達成の仕組みは付けない。

- 一覧は、ビルド時に species.json から作る全種の見出し（`virtual:species-index`。`vite/contentModules.ts` と `src/core/speciesIndexEntry.ts`）だけで描き、図鑑を開いたときに1つのチャンクとして読む（254種で約120KB、gzip 24KB。体の画像の URL の表 `virtual:fish-images` も一緒に読む）。見出しには、見られる水槽（`tankIds`）と展示順（`exhibitRank`）もビルド時に入れる。解説を開いたときに、その種のモジュール（`virtual:species/<id>`）を読む。
- 種数は、表示用の学名とは別の「種として数えるキー」（`speciesKey`）で数える。亜種は種にまとめ、未同定（sp.）・種群・流通名は数えない。

### 6. アセットの保管庫と制作キュー

数百種の画像を外部のエージェントに夜間などにまとめて作らせ、手元で確かめて取り込めるようにする。原画はリポジトリの外の保管庫（非公開リポジトリ `sakataka/aquarium-assets`）に置き、このリポジトリには配信用の `body.webp` と `plate.webp` だけを入れる。今の `side.png` は合計55MBあり、数百種では数百MBになるため。フォルダ構成、依頼の書式、状態の進め方、取り込みの手順は [アセットの保管庫](asset-vault.md) にまとめる。

### 数百種に耐えるための決まり（2026年10月5日に実装、10月7日に作り直し）

起動時に読むものを、館内図に要るものだけに絞る。展示室の中身は、その展示室に入るときに読む。内容ファイル（`src/content/`）はビルド時に `vite/contentModules.ts` が読み、zod で形と参照（水槽の水景と生き物、展示室の水槽、館の枠）を検証して、次のモジュールを作る。形の定義は `src/core/contentSchemas.ts`（生き物は `src/core/schema.ts`）にあり、ビルドとテストで使う。アプリは検証済みの内容を読むだけで、起動時に zod を読まない。

| モジュール | いつ読むか | 中身 |
|---|---|---|
| `virtual:museum`（`core/museum.ts`） | 起動時 | 館（`museum.json`）、展示室の見出し（名前、階、水槽の並び、生き物の数）、階ごとの生き物の数、水槽の見出し（名前、展示室、選べる水景）、階と展示室を読む関数 |
| `virtual:floor/<id>`（`core/museum.ts` の `loadFloor`） | 館内図で階を開くとき（触れたときに先読み）と、その階の展示室に入るとき | その階の展示室の部屋の絵のガラスの位置と縮小版の画像、その階の水景の見出し（縮小版の画像、既定の照明、切り取り方） |
| `virtual:hall/<id>`（`core/catalog.ts` の `loadHall`） | 展示室に入るとき | 水槽の定義、水景（見出し、地形、`plate.webp` の URL）、生き物の定義、部屋の絵の URL。1つのチャンクにまとめ、入るときの読み込みを1回にする（階のモジュールと並べて読む）。読み終わるまでは「展示室を準備しています」を出す |
| `virtual:fish-images` | 最初に展示室か図鑑を開くとき | 全種の体の画像（`body.webp`）の URL |
| `virtual:species-index` | 図鑑を開くとき | 全種の見出し（上の「図鑑のデータ」） |
| `virtual:species/<id>` | 図鑑で解説を開くとき | 生き物1種の定義 |
| 展示室と水槽の描画（PixiJS を含む） | 展示室に入るとき | 館内図にいる間に先読みする |

- 最初に読む JS は 285KB、gzip で89KB（2026年10月7日、18室・70水槽・78水景・254種）。react が約219KB、館の索引が約20KBで、残りがアプリの画面と保存。以前は 640KB（gzip 188KB）で種と水槽の数に比例して増え、10月7日の分割で 314KB（gzip 99KB）になり、同じ日にガラスの位置と水景の見出しを階のモジュールへ移して今の大きさになった。館の索引は展示室と水槽の数に比例し、生き物と水景の数では増えない。約200水槽・35室になっても 60KB 前後（gzip 15KB 前後）の見込み。階のモジュールは1階分が 2.5〜10KB（gzip 1〜5KB）。
- `package.json` の `sideEffects`（CSS だけに副作用がある）で、`src/core/index.ts` から再輸出しているだけで館内図では使わないシミュレーションなどを、最初のチャンクから外している。CSS 以外で、読み込むだけで効くモジュールを作らない。
- 保存データの水槽ごとの設定は、その水槽のある展示室に入るときにそろえる（`normalizeHallCustomizations`）。起動時には、水景がその水槽で選べるか（選べなければ最初の水景にして照明を残す）と照明の形だけを確かめ、照明の壊れた水槽の設定は落とす（既定の照明は階のモジュールにあり、起動時には分からないため）。入ったことのない展示室の水槽の設定は持たない。館内図の縮小版は、設定がなければ水槽の最初の水景を映す。
- 前の展示室のテクスチャ（部屋の絵、水景、魚）は、展示室を移ったときに GPU から外す（`render/assets.ts` の `releaseTexturesExcept`）。館内図にいる間は、直前の展示室の分を残す。
- 館内図の縮小版は、部屋の絵の小さな版（`room/thumbs/`、幅960px）と水景の `thumb.webp` だけを読み、画面外のものは遅れて読む。
- 魚種・水槽・展示室の追加は、これまでどおりファイルを置くだけで済み、中央の一覧ファイルを編集しない。開発サーバーでは、内容ファイルを足す・変える・消すとモジュールを作り直して読み直す。参照切れや形の誤りは、ビルドと開発サーバーがファイル名つきで止める。
- テストは `src/core/testSetup.ts` で全展示室と全生き物を先に読んでから検査する（`getLoadedTanks`）。
