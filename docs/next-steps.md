# これからの進め方（約1,300種に向けて）

新しい作業スレッドに渡すための方針。スレッドを始めるときは、この文書と、作業に関係する文書（下の「読むもの」）を読んでから始める。進み具合に合わせて、この文書を書き換える。2026年10月7日時点。

## 今の状態

- 館は地上4階・地下2階、18室。18室すべてを開けた。魚とエビ（エビの描き方で歩く甲殻類を含む）の70水槽に254種がいる。
- 魚以外の生き物を待つ14水槽は、展示室の絵のガラスに水景を暗く焼き込んで「準備中」として見せている（cold-crabs-180、giant-octopus-180、cold-jellies-90、reef-invertebrates-90、seahorse-90、octopus-squid-120、sea-jellies-60、clione-30、japan-stream-crab-45、giant-salamander-240、nautilus-120、horseshoe-crab-180、deep-cephalopods-120、deep-jellies-90）。
- 保管庫（`~/Documents/aquarium-assets`）には dots が作った生き物が約300種あり、魚は採用してアプリに入れた。魚以外（カニ、クラゲ、タコ、両生類など約60種）は、体のつくりができるまで採否を保留している。
- dots は約1,300種を目標に制作を続けている（2026年10月6日時点で2割5分ほど）。あと3〜4日かかる見込み。保管庫の種のフォルダは2026年10月7日に366種。
- 水面の上の空気まで見える水景（マングローブ、干潟）は、`scene.json` の `waterLine` で水面の高さを持ち、魚は水の部分で泳ぐ（[設計の「水の種類」](museum-architecture.md#4-水の種類をデータで決める)）。
- 2026年10月7日に、dots の形態レビューの依頼に一括で返事をし、採否の基準を保管庫の `consumer/app-requirements-ja.md`「形態の確認の基準」に書いた（画面で見える大きさで判断し、輪郭が変わる修正は新しい生成で、1つの修正は2回まで）。その返事で「採用候補」とした種（ミズウオ r2、キンメダイ r2、ギバチ、ヨーロッパスナヤツメ、ヨーロッパカワヤツメ、コトブキテッポウエビ、アカモンミノエビ）は、まだ `adoptions/` に記録しておらず、アプリにも入れていない。置く水槽を決めるときに取り込む。シミリスは shell-dwellers-45 に入れると返事した。

## 方針

- **約1,300種を前提に設計する。** 当面の目標は第1弾の約250〜300種を完成させることだが、作り方は1,300種で破綻しない形を選ぶ。
- **互換性は気にしない。** 保存データ、水槽ID、展示室ID、ファイルの形は、よりよい設計のためなら変えてよい（利用者は開発者本人だけ）。古い保存データの移行処理も消してよい。
- **データで決める。** 展示室・水槽・水景・生き物は `src/content/` のファイルを置けば読み込まれる形を保つ。中央の一覧ファイルを手で編集する形にしない。取り込みはスクリプトで行う（[アセットの保管庫](asset-vault.md#展示室を開ける流れ)）。
- **画像は dots が作る。** アプリ側で画像を生成しない。足りない画像や直してほしい点は、保管庫で dots に伝える（下記）。
- 起動時に読むものを増やさない。展示室の中身は、その展示室に入るときに読む。

## dots とのやりとり（毎回の作業の始めに）

1. `cd ~/Documents/aquarium-assets && git pull` のあと、`notes/to-claude-code/` を見る。`consumer/replies/` に同じ名前の返事がないものが未対応。
2. 判断を返す。返事は `consumer/replies/<同じファイル名>` に置く。
3. 不足や不備は、返事か、`revisionTarget` 付きの修正依頼（`queue/requests/app-review-NNN.b1.json`、`queue/schemas/request.schema.json` で検証する）で伝える。構図を保ったまま一部だけ直す編集を頼むと、アプリ側の地形を作り直さずに済む。
4. 採否は `adoptions/` に記録する。保管庫の変更も commit・push する。

## 届いた生き物を取り込む手順

1. **確かめる**: 未採否の種の最新草案（`species/<id>/meta.json` の `variants`）を、灰色の背景に重ねたコンタクトシートで目視する。外接矩形と余白（alpha 16 を超える画素、四辺48px）も数値で見る。依頼文（`catalog/*.json` の `subjectEn`）と模様・ひれの数が合っているかを見る。
2. **採用を記録し、取り込む**: `adoptions/<id>.json` を書き、`AQUARIUM_ASSET_VAULT=~/Documents/aquarium-assets uv run scripts/install-vault-species.py <id>...` で `content-drafts/fish/` に入れる。
3. **下書きを書く**: `species.json` を調査（research.json）から書く。5種ずつサブエージェントに分けると速い。事実は調査に出典のあることだけを使い、動きの値は近い既存種に合わせる。`src/core/drafts.test.ts` が形を検証する。
4. **水槽に入れる**: 展示計画（`catalog/exhibit-plan.json`）の水槽の `species` に足し、`content-drafts/fish/<id>/` を `src/content/fish/` へ移し、`tank.json` の `species`・`defaultStock` に足す。

## 展示室や水槽を足すとき（地形づくりの注意）

手順は [アセットの保管庫](asset-vault.md#展示室を開ける流れ)。地形（`terrain.json`）は1水槽ずつ絵を見て作る。展示室ごとにサブエージェントに分けて並行して作り、次を守らせる。

- 見える範囲（ガラスの縦横比で cover し、`framing.plateBottom` を下端に合わせた範囲）を切り出した絵で座標を決め、地形を重ねた確認画像で合わせる。
- 回避領域（obstacles）は魚の体長×0.2 だけ広げて判定される。楕円どうしの重なりのくぼみや、楕円とガラス・底の細いすき間に魚が挟まると、押し出されて位置が飛ぶ（耐久テストで落ちる）。大型魚の水槽ほど、大きな楕円を少数置き、壁や底まで覆う。
- 隠れ場所は、どの魚の体長で判定しても回避領域の内側に入らない奥行きに置く。`homeShelter` の魚がいる水槽には、その種類の隠れ場所が要る。
- エビなど面を歩く生き物は、端点でつながった面しか移れない。
- テストは最初の失敗で止まるので、担当の水槽だけに絞った一時テストを作って流し、終わったら消す。
- 名前は「〜水槽」、`category` は生息地の名前、照明は夜行性の多い水槽なら `evening` も検討する。
- 水面の上の空気まで見える絵なら、`scene.json` に `waterLine`（手前と奥の水面の高さ）を書く。泳ぐ層は水の部分に対する比率になるので、空気の分を避けて層を下げない。回避領域の上端が水面のすぐ下まで来ると、魚が水面との間に挟まりやすい。
- 展示室1室の既定の匹数は合計180匹までを目安にする（iPhone で全水槽を同時に描くため）。

## 次にやること（優先順）

新しいスレッドには、番号を指定して頼む。

1. **図鑑を見られるようにする**: 以前あった魚の図鑑の画面（`src/ui/FishGuideView.tsx`）は、2026年9月2日の鑑賞向けへの作り替え（a4aec44）で外し、今は水槽の設定パネルの魚のカードに学名・動き・原産地が少し出るだけになっている。図鑑の中身（`species.json` の `profile`：分類、大きさ、分布、水温と水質、飼育区分、保全状況、見どころ、出典）は、新しく足した219種には書いてあるが、最初からいた35種にはまだない。[ロードマップ](roadmap.md)の手順7と[設計の「図鑑のデータ」](museum-architecture.md#5-図鑑のデータ)に沿って、全種の一覧と検索、1種ずつの解説、どの水槽で見られるか（そこから水槽へ移る）を持つ画面を作り、`?zukan=<species-id>` で開けるようにする。収集や達成の仕組みは付けない。全種の一覧に要る軽い索引は、2番の「起動時に読むJSを減らす」と一緒に設計する。35種の `profile` は保管庫に調査がないので、公開資料から出典つきで書く（dots に調査を頼んでもよい）。
2. **起動時に読むJSを減らす**: 最初に読むJSが、426KB（35種）→ 637KB（254種、gzip 187KB）と種と水槽の数に比例して増えた。全水槽の `tank.json`、魚種ごとの画像URLと読み込み関数の表が起動時に入っている。館内図に要る軽い索引（展示室・水槽の名前と数）だけを起動時に読み、水槽の定義と魚種の表は展示室ごとのチャンクに分ける。図鑑の全種索引もここで設計する。
3. **魚以外の体のつくり**: 準備中の14水槽を開けるため、カニ（エビの歩行を流用）から始め、クラゲ、タコ・イカ、タツノオトシゴ、エイ、両生類、チンアナゴ（砂から出入り）と順に足す。手順は [設計の「体のつくり」](museum-architecture.md#3-体のつくり実装済み)。保管庫に画像と調査がある種から採用する。
4. **1,300種に合わせた館の拡張**: 1水槽5〜8種・1室6水槽までなら、約200水槽・35室前後になる。展示計画を広げる（別館や東西の翼）。館内図は、全体の断面図から階を選び、階の中の展示室を一覧する2段の形にする（今もスマホ幅では、4室並ぶ階の展示室名が途中で切れる）。展示室・水槽の追加は dots に絵を頼む。dots への返事で作ると伝えた水槽がある: 枝状ミドリイシのある小型のサンゴ礁水槽（キイロサンゴハゼなど）と、日本の川の展示室のテナガエビ類の水槽（ヒラテテナガエビ、ミナミテナガエビなど）。
5. **地形づくりの省力化**: 1水景ずつ手で輪郭を取るのが律速。dots に水景と一緒に前景のマスク（手前の岩・流木の領域）や底の線を出してもらい、遮蔽と面を自動で作る仕組みを検討する。
6. **シミュレーションの不具合と不足**: 休んでいる魚が少しずつ岩の内側へ入り、外へ押し出されて位置が飛ぶ（今は地形の調整でテストを通している）。岩に吸着して休む習性がない（ダンゴウオが砂の上で休む）。大型魚が水槽に対して大きすぎて縁で切れる（深海の大型種）。
7. **後始末**: 古い保存データの移行処理（v4 からの移行、7水槽時代の構成の入れ替え）とそのテストを消す。`scripts/verify-webview.ts` の古い移行の検証も外す。
8. **規模への備え**: 数百種を超えたら、配信用画像の置き場所（Git の履歴の重さ）とテスト時間を見直す。

## 検証

- 変更ごとに `bun run test`、`bun run build`（型検査を含む）を通す。画面に関わる変更は `bun run verify:webview`（WebKit。全展示室を 1440×960 と 420×912 で開き、全水槽に出入りする。20分ほどかかる）。
- 画面検証の実行中は、開発サーバーの再読み込みで結果が崩れるので、ソースを編集しない。
- ブラウザで見るときは localStorage を消してから見る（古い既定の匹数が残るため）。
- 変更は検証のあと commit・push する。保管庫の変更も同様。
