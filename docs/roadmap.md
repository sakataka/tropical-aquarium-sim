# ロードマップ

作業スレッドを始めるときの方針と、優先順の作業一覧は [これからの進め方](next-steps.md) にある。

自宅のフィッシュルームから架空の展示館「水の生き物館」（仮称）へ移り、生き物を数百種まで増やしていくための進め方。方針は [開発方向性](development-directions.md)、設計の詳細は [水の生き物館 設計](museum-architecture.md) にある。2026年10月5日時点。

## 目指す姿

- 館内図から階と展示室を選び、身近な水辺から海、冷たい水、地下の特別展示（生きた化石、洞窟と深海）まで、見慣れない生き物に出会える。
- 生き物は実在のものだけで、見た目と動きはリアル。魚だけでなく、エビ、カニ、クラゲ、タコ、両生類など、水の中の生き物を幅広く扱う。
- 図鑑で、分類・分布・生息環境・保全状況・展示で見られる行動を、出典つきで学べる。
- 館長として、水槽ごとの生き物・水景・照明を組める。
- 画像は外部のエージェントにまとめて作ってもらい、手元で確かめて取り込む。数百種でもリポジトリと制作の流れが破綻しない。

## 長期目標: 約1,300種（2026年10月5日に決定）

日本で飼育種類数が最も多いとされる鳥羽水族館（約1,200種）を超える、約1,300種を目指す。実際の水族館では飼えない・展示例のない生き物（ジンベエザメのような大型種、リュウグウノツカイや深海魚など）も載せられることを、この館の強みにする。まずは第1弾の約250種（200種＋既存35種＋小さな生き物など）を丁寧に仕上げ、その後 dots に少しずつ増やしてもらう。

1,300 という数にはこだわらない（1,400でも1,500でもよい）。目指すのは「ふつうに見聞きする水の生き物は、ひととおりそろった」と感じられる館である（2026年10月8日、ユーザーより）。

### どの種も、館のどこかで必ず見られる（2026年10月8日、ユーザーより）

図鑑に載る種は、どれも少なくとも1つの水槽に展示し、その水槽へ行けば最低1匹は見られるようにする。匹数は1匹でもよい。図鑑には載っているのに館のどこにもいない種は作らない（実際の水族館なら「今は展示していない」もありうるが、この館では原則にしない）。図鑑から水槽へ飛べるリンクは必須ではないが、図鑑で知った種を探しに行けば会える状態を保つ。

この原則を守るために、種数が増えるほど次を前もって考える。

- **器の数**: 種数に合わせて、水槽・展示室・階・建物（別館や翼）を足せる形にする。種を入れる先がないから図鑑だけに載せる、ということが起きないように、展示計画（保管庫の `catalog/exhibit-plan.json`）を種の受け入れより先に広げる。
- **拡張性**: 水槽・展示室・建物を足しても、館内図・URL・データの形を作り直さずに済むようにする（今の「階 → 展示室 → 水槽」の階層の上に、建物の段を足せること）。
- **性能**: 水槽と展示室が数百に増えても、起動時に読むものと、1つの展示室で同時に描くものが増えないようにする（今の、展示室に入るときに読む形を保つ）。
- **アーキテクチャと検査**: 「図鑑の全種が、どこかの水槽の `species`（入れられる種）と既定の匹数に入っている」ことをテストで確かめられるようにする。展示計画で置き場所の決まっていない種は、取り込む前に置き場所を決める。

増やすときの見込み（いま決めることではなく、設計の前提として持っておく）:

- **展示室と階**: 2026年10月10日に、館を本館・海の館・川と湖の館の3つの建物にし、展示計画を50展示室・254水槽へ広げた（[設計](museum-architecture.md#建物と階の構成)）。それまでの見込み（1水槽5〜8種、1展示室6水槽で約200水槽・35室）より多いのは、今の密度（水槽1つに4〜5種）に近い数で器を用意したため。館内図は、建物を選び、その建物の断面図から階を選び、階の中の展示室を一覧する形。建物を足しても URL と保存データの形は変わらない。部屋の絵のガラスの位置は階ごとのモジュールに分け、起動時の館の索引は水景の数で増えない。
- **制作の律速は調査**: dots によると、画像は速いが、生態の調査は世界の論文や資料を探すので時間がかかる。調査の質は落とさず、時間がかかってよいものとして計画する。
- **読み込み**: 魚種と地形は展示室ごとに読む形にしてあるので、種数が増えても最初の読み込みは増えない（[設計](museum-architecture.md#数百種に耐えるための決まり2026年10月5日に実装)）。図鑑を作るときは、全種の一覧と検索に使う軽い索引（名前、学名、分類、どの水槽にいるか）を別に生成する。
- **リポジトリの大きさ**: 配信用の `body.webp` は1種あたり約60KBで、1,300種で約80MB。水景・展示室の画像を合わせても GitHub Pages の上限（1GB）には収まるが、Git の履歴が重くなるので、数百種を超えたら配信用画像の置き場所（Git LFS や、保管庫からビルド時に取り込む形）を見直す。
- **テストの時間**: `content.test.ts` などは種数に比例して遅くなる。全件の検査は残しつつ、遅くなったら並列化する。
- **体のつくり**: 魚とエビ以外（カニ、クラゲ、タコ・イカ、エイ、両生類、チンアナゴのような砂から出入りする魚など）を順に足す。知名度の高いチンアナゴ（`burrower`）とクリオネ（羽ばたく泳ぎ）は早めの候補。

## 決まったこと

- 舞台は架空の展示館。利用者は館長で、今の設定操作を残す。
- 架空の生き物は載せない。絶滅種の復元は当面載せない。深海の生き物と、魚以外の水の生き物は載せる。
- 図鑑は生態を学べる内容にし、収集や達成の仕組みは付けない。
- トップは地上4階・地下2階の断面図の館内図。階を選ぶと、その階の展示室を縮小版つきで並べ、まだない展示室は準備中と出す。地下は特別展示のゾーン。展示室の絵は展示館の内装で描き直す。
- 原画はリポジトリの外の保管庫（`sakataka/aquarium-assets`）に置く。
- 本館は地上4階・地下2階、18展示室、84水槽（2026年10月5日）。上から冷たい水、サンゴ礁と海、世界の川と湖、日本の水辺、地下に生きた化石と洞窟・深海。展示計画の正本は保管庫の `catalog/exhibit-plan.json`。
- 館は本館・海の館・川と湖の館の3つの建物（2026年10月10日）。海の館は地上3階・地下2階（サンゴ礁の世界、世界の岸辺、外洋、背骨のない生き物、深い海）、川と湖の館は地上3階（北の大陸の川と湖、熱帯の川をもっと、人と水辺）。本館にも3室（北の川とサケの遡上、琵琶湖と日本の湖、琉球の川と河口）を足す。計画は50展示室・254水槽。新しい建物の断面図は Codex の画像生成で作った。
- 水草と海藻は種として足さず、水景の一枚絵の中で産地に合わせて描く。
- 最初の魚以外の生き物はカニ（2026年10月8日）。dots の斜め上から見た3/4の画像（前が左）を使い、向きを保ったまま横歩きさせる。
- 続いてクラゲ（2026年10月8日）。dots の真横の画像（傘が上）を反転せずに使い、傘の拍動で進んで開く間に沈む。
- 続いてタコとイカ（2026年10月8日）。タコは dots の斜め上から見た3/4の画像で、口を中心に腕をうねらせて底を這い、驚くと胴を先に噴射で飛び退く。イカ・オウムガイ・コウモリダコは真横の画像で、ひれを波打たせて向きを保ったまま前へも後ろへも泳ぐ。メンダコは膜を拍動させるクラゲの漂い方で泳ぎ、ときどき底に伏せる。
- 生き物の情報（学名の変更、大きさ、分布、保全状況など）を新しくして図鑑と展示に反映する仕組みは、館がひととおりそろってから作る（2026年10月9日、ユーザーより）。手順は [これからの進め方](next-steps.md) の「次にやること」。

## 決まっていないこと

- 館の正式な名前（今は仮称「水の生き物館」）。
- 海と淡水の爬虫類・哺乳類・鳥（ウミガメ、ペンギン、アザラシ、イルカ、ワニ、カワウソ、カモノハシなど）を載せるか。設計は「魚以外の水の生き物も載せる」としているが、例に挙げていたのは無脊椎動物と両生類まで。載せるなら体のつくりと画像の視点が新しく要る。置けそうな水槽の案は展示計画の `undecided` にある。淡水のカメだけは、まだ描けない体のつくり（`needs: "turtle"`）の候補として計画に入っている（外来のカメの水槽など）。
- 改良品種（金魚・メダカ・錦鯉・ベタ・グッピーなどの品種）を、図鑑で別の種として数えるか、同じ種の別の姿（variant）として扱うか。川と湖の館の「金魚と錦鯉」の展示室を開ける前に決める。
- 外来種を、日本の水辺の水槽（外来種の水辺）と原産地の水槽の両方に置くか（1種を2水槽に置くのは仕組みの上では問題ない）。
