# 地形の下書き

水景の絵（`plate.webp`）だけから、地形（`terrain.json`）の下書きと、絵に地形を重ねた確認画像を作る道具 `scripts/draft-terrain.py` の仕組み、使い方、評価の結果をまとめる。評価は2026年10月10日、手書きの92水景を正解として行った。

結論を先に書く。

- 下書きは「確認して手直しする出発点」として使える。そのまま採れるものは少ない。
- 砂の面（底の線）はよく取れる。手前の岩や流木の輪郭（遮蔽）は、岩の多い水景ならおおむね取れる。
- 回避領域と隠れ場所は置き場所の目安にとどまる。巣穴・イソギンチャク・海草の茎・水面より上の岸は作れない。
- 下書きに差し替えた92水景すべてで、水槽の耐久テスト（`bun run test:tanks`）は通った。ただし、回避領域の置き方はこの92水景で落ちなくなるまで調整したものなので、新しい水景でも通るとは限らない。

## 使い方

```sh
# 下書きと確認画像を作る（複数可）。--compare で既存の手書きの地形を並べる
uv run scripts/draft-terrain.py <水景id>... [--compare] [--debug]

# 画像のパスでもよい。ガラスの縦横比と plateBottom を仮に指定できる
uv run scripts/draft-terrain.py path/to/plate.png --aspect 2.4 --plate-bottom 0.9

# 案内の絵（遮蔽にする物体の塗り分け版、隠れ場所の印の版）があれば渡す。水景は1つだけ
uv run scripts/draft-terrain.py <水景id> --occluders occluders.png --shelters shelters.png

# 面を歩く生き物（エビ・カニなど）だけの水槽向け。上面を出さず、砂の面を斜めの道でつなぐ（どちらも既定は切）
uv run scripts/draft-terrain.py <水景id> --no-tops --connect-sand

# 既存の手書きの地形と比べて数字を出す（省くと全水景）
uv run scripts/draft-terrain.py evaluate [<水景id>...]

# 既存の手書きの地形の統計
uv run scripts/draft-terrain.py stats
```

出力は `tmp/terrain-drafts/<id>/`（Git 管理外）。

| ファイル | 中身 |
|---|---|
| `terrain.json` | 下書き。`src/content/environment/scenes/<id>/terrain.json` と同じ形 |
| `overlay.jpg` | 確認画像。面は線（色は depth。赤が手前、青が奥）、遮蔽は半透明の多角形と depth、回避領域は白い楕円と「中心の depth ± 奥行きの半径」、隠れ場所は紫の×、寄り道先は水色の丸。黄色の枠が前面ガラスに映る範囲で、枠の外は暗くしてある |
| `notes.txt` | 人が必ず見るべき点（作れなかった隠れ場所の種類、単体テストに掛かりそうな遮蔽など） |
| `debug.jpg` | `--debug` を付けたとき。底（青）と物体（赤、太い部分は黄）のマスクと、奥行きの推定 |

`src/content` の `terrain.json` は書き換えない。書き換えるのは `--write` を付けたときだけで、既存の水景にしか使えない。新しい水景で使う流れは次のとおり。

1. `scripts/install-vault-scene.py` で水景を取り込み、`tank.json` と部屋の絵（`room/<hall>.json`）を置く。ガラスの縦横比、`framing.plateBottom`、`waterLine`、水槽の生き物が住みかにする隠れ場所の種類は、ここから読む。部屋にまだ置いていない水槽は、水槽の幅と高さの比で代用する（`--aspect` で指定もできる）。
2. `uv run scripts/draft-terrain.py <id>` で下書きを作り、`overlay.jpg` と `notes.txt` を見る。
3. `tmp/terrain-drafts/<id>/terrain.json` を手で直す（下の「人が必ず見るべき点」）。または `--write` で置いてから直す。
4. `bun run test:tanks -- -t <水槽id>` と `bun run test:fast` で確かめる。

初回は奥行き推定のモデル（約100MB）と Python の依存（torch など）を取りに行く。奥行きの推定結果は `tmp/terrain-drafts/.cache/` に置き、2回目からは使い回す。

## 仕組み

1. **奥行きの推定**: Depth Anything V2 Small（Apache-2.0。Hugging Face の `depth-anything/Depth-Anything-V2-Small-hf`）で、絵の画素ごとの視差（大きいほど手前）を出す。
2. **見える範囲**: `src/core/plateFraming.ts` の `framePlate` と同じ計算で、前面ガラスに映る範囲を求める。`waterLine` があれば、手前の水面より上は解析しない。
3. **底の面**: 行ごとに、見える範囲の視差の低い側（12%点）を取り、下の行ほど手前になるようにそろえて「行ごとの底の視差」とする。底はその行に見えているもののうちいちばん奥にある、という性質を使う。各画素について、同じ視差の底が何行下にあるか（底からの高さ）を求め、高さがほぼ0のところを底、見える高さの5.5%以上立ち上がるところを物体とする。
4. **開けた水を物体にしない**: きめ（局所的な明るさのばらつき）のないところと、絵全体で見て十分に手前でないところは、物体から外す。奥行きの推定は、暗い水や広い水に「周辺ほど手前」のゆるい勾配を付けることがあり、それだけでは水の中に遮蔽ができる（深海の大水槽、黒潮の大水槽で起きた）。手書きの遮蔽のきめは最小でも 5.6、水と読み違えた候補は 1 未満で、はっきり分かれた。
5. **近さの換算**: 見える範囲の下端の底を0、いちばん遠い水を1とする近さ u を作り、砂の面の depth は手書きの砂の点から決めた折れ線（u 0.25 → 0.22、0.4 → 0.45、0.7 → 0.72 など）で、岩や流木の depth は直線（0.33 + 0.27u）で決める。
6. **砂の面**: 手前の面は見える範囲の下端のすぐ上（ガラスの安全余白 2cm の内側）に置き、下端が物体で埋まっている列では底が見え始める高さまで上げる。中（depth 0.45）と奥（0.72）の面は、その depth に当たる視差の底を列ごとに探して等高線をなぞる。底が見えている区間だけを残す。
7. **遮蔽**: 物体を近さで手前・中・奥の3段に分け、手前から「そこまでの物体」を重ねた輪郭を多角形にする。細い茎や枝、底に沿った薄い帯、水面から垂れるだけのものは落とす。最大6個。
8. **岩や流木の上面**: 遮蔽にした物体の上の輪郭のうち、なだらかな区間を面にする（depth は遮蔽の少し手前）。茶色く細長い物体は流木、ほかは石とする。寄り道先は上面の中ほどに置く。
9. **回避領域**: 手前と中の物体の太い部分ごとに、軸に平行な楕円を1つ置く（画素の広がりの1.2倍）。ガラスの近くまで来る楕円はガラスの外まで伸ばし、近すぎる楕円はまとめるか引き離し、砂の面に掛かる楕円は削る。depth は、遮蔽の面のすぐ奥から芯が始まるように置く。
10. **隠れ場所**: 遮蔽にした物体の足もとのいちばん暗いところを、回避領域の楕円の外（魚の体長ぶんの余白も外）に置く。水槽の生き物が cave / crevice を住みかにするなら、その種類を付ける。

数字を読むときの注意。

- 近さの換算の折れ線と直線は、この92水景から決めた。水景を2組に分けて片方で決め、もう片方で測ると、砂の点の depth の誤差は 0.09〜0.14 だった（一律に中央値を当てると 0.20）。
- 手書きの遮蔽は、絵にある物体のうち人が選んだ一部で、輪郭もおおまかに取ってある。下書きの適合が 0.6 にとどまるのは、下書きが水草のかたまりや奥の岩まで遮蔽にするため。IoU は「人と同じ物を選んだか」を強く反映し、輪郭の正確さだけを測ってはいない。
- 岩や流木の depth は、手書きの値そのものが遠近と弱くしか対応しない。一律に 0.4 を置いても誤差は 0.11 で、下書きの 0.10 と大差がない。
- 回避領域は、手書きが「岩の中に小さな楕円をいくつか」置くのに対し、下書きは「かたまりごとに1つ」置く。置き方の考え方が違うので、一致は低い。

### 手書きとの近さの区分

面と遮蔽だけで決めた区分（回避領域と隠れ場所は、いつも人が見直す前提なので入れていない）。

- 近い: 手前の線が取れ、手書きの砂の面がすべて対応し、遮蔽の IoU が 0.6 以上（どちらにも遮蔽がない場合を含む）
- 手直し: 手前の線が取れ、遮蔽の IoU が 0.3 以上
- 大きく違う: それ以外

| タイプ | 近い | 手直し | 大きく違う |
|---|---|---|---|
| 全体（92） | 24（26%） | 36（39%） | 32（35%） |
| 岩が中心（50） | 12 | 21 | 17 |
| 流木・水草が中心（24） | 6 | 12 | 6 |
| 開けた砂底・泥底（11） | 3 | 1 | 7 |
| 水面の上まで見える（3） | 0 | 2 | 1 |
| 縦長のクラゲ水槽（4） | 3 | 0 | 1 |

「大きく違う」には、下書きが悪いものと、手書きと選び方が違うだけのものが混ざる。たとえば kelp-forest-400 や amazon-driftwood は、手前の線を置いた高さが手書きと違うために「大きく違う」になるが、確認画像で見ると下書きの面も底に乗っている。逆に「近い」でも、回避領域と隠れ場所は見直しが要る。

### 使える割合の見立て

上の区分と、確認画像およそ15枚を目で見た印象からの見立て。測った数字ではない。

- そのまま使える: 1割に届かない。底だけの水景（クラゲの水槽、物のない深海）に限られる。
- 手直しで使える: 6〜7割。砂の面はほぼそのまま、遮蔽は要らないものを消して depth を整え、回避領域と隠れ場所を見直す。
- 作り直しに近い: 2〜3割。根や茎が林立する水景、水草が画面を埋める接写、巣穴・海草・イソギンチャクが主役の水景、見える範囲のほとんどが水の大水槽。

### 下書きで動くか

92水景すべての `terrain.json` を下書きに差し替え、`bun run test:tanks`（上限匹数での昼夜20分を2通りの乱数で、既定の匹数での3分を1回）を流した。確かめたあと元へ戻した。

| 回避領域の置き方 | 通った水景 |
|---|---|
| 回避領域なし（面・遮蔽・隠れ場所だけ） | 92/92 |
| 楕円を底とガラスまで伸ばし、近い楕円はまとめる（広がりの1.5倍） | 85/92 |
| 楕円を物体の中に収める（1.2倍）。隠れ場所は楕円の内側 | 90/92 |
| 上に加えて、隠れ場所を楕円の外に置き、ガラスの近くだけ伸ばす | 91/92 |
| 上に加えて、砂の面に掛かる楕円を削り、楕円の芯を遮蔽の面の奥に置く（今の既定） | 92/92 |

落ちた理由はどれも「魚が回避領域の縁で1秒を超えて止まる」だった。分かったこと。

- 行き先（隠れ場所、底で休む砂の面）が楕円の内側（x・y）にあると、魚は同じ奥行きのまま近づけず、縁で止まり続ける。手書きの地形でも、砂の面が楕円の内側に入る点は5%しかない。
- 岩の上面は楕円の内側にあってよい（手書きでは28%）。ただし奥行きでは楕円の手前に置く。手書きの「遮蔽の面と上面 → そのすぐ奥に芯 → さらに奥に隠れ場所」の並びに合わせると通る。
- 楕円を底まで伸ばし、近い楕円を1つにまとめると、かえって落ちる水景が増えた。大きな楕円が泳ぐ場所と行き先を覆うため。

差し替えたまま `bun run test:fast` を流すと、手書きの地形の id や座標を前提にした単体テスト（13件）が落ちる。新しい水景には関係しないが、次の2つは新しい水景でも掛かる。

- 「住みかにする隠れ場所の種類が水景にある」: burrow・anemone・holdfast は下書きに出ないので、人が置くまで落ちる（92水景中9水景）。
- 「どの遮蔽も絵の (0.5, 0.3) と (0.15, 0.99) を覆わない」: 9水景で、下書きの遮蔽が手前の底の隅 (0.15, 0.99) などを覆った。`notes.txt` に出る。

「面と隠れ場所がガラスの内側に見えている」「隠れ場所が岩の内側にない」は、92水景すべてで通った。

## どこまで任せられるか

| 要素 | 任せられる度合い | 理由 |
|---|---|---|
| 手前の砂の面 | ほぼ任せられる | 77%が手書きと同じ高さ。外れは、手書きが下端より上の「砂の見えている所」に線を置いた水景 |
| 中・奥の砂の面 | 下書きを直す | 位置は合うが、手書きより長く引く。depth は ±0.1 |
| 遮蔽の輪郭（岩、太い流木） | 下書きを直す | 輪郭は絵に合う。要らないものを消し、段を選ぶ |
| 遮蔽の輪郭（水草、根、海藻） | 人が選び直す | 草むら全体を1枚の遮蔽にしてしまう |
| 遮蔽の depth | 人が決める | 手書きの値が設計の判断で、絵からは決まらない。下書きは 0.3〜0.6 の仮の値 |
| 岩・流木の上面 | 人が足す | 手書きの4割しか出ない |
| 回避領域 | 人が見直す | 数が少なく（1.6 対 2.6）、置き方も違う。耐久テストは通る |
| 隠れ場所（cave / crevice / 種類なし） | 置き場所の目安 | 「物体の足もとの暗がり」を置くだけ。洞窟の口を見つけてはいない |
| 隠れ場所（burrow / anemone / holdfast） | 人が置く | 絵から決められない |
| 水面より上（岸の面、水の外の巣穴）、`waterLine` | 人が書く | `waterLine` は `scene.json` から読むだけで、推定しない |
| 泡の出どころ | 人が置く | 出さない（手書きでも1割） |
| 面どうしのつなぎ | 人がつなぐ | 既定では端点をそろえない（手書きでも13水景だけ）。面を歩く生き物だけの水槽は `--connect-sand` で砂の面どうしをつなげる |

## 案内の絵を使う（2026年10月10日）

水景を作るときに、同じ絵を編集した「案内の絵」を2枚作ってもらい、下書きの道具に渡せる。

```sh
uv run scripts/draft-terrain.py <水景id> --occluders <塗り分け版.png> --shelters <印の版.png>
```

| 案内の絵 | 中身 | 下書きでの使い方 |
|---|---|---|
| 塗り分け版（`--occluders`） | 魚が後ろに隠れる物体（岩、太い流木、根の塊）だけを、影も質感もない単色で塗る。手前=赤 #FF0000、中=黄 #FFFF00、奥=青 #0000FF。砂、小石、細い水草、水は元のまま | 遮蔽と回避領域を、奥行きの推定ではなく塗られた物体から作る。塗られた物体を1つずつ別の遮蔽にする（下の「塗り分け版を物体ごとに分ける」） |
| 印の版（`--shelters`） | 隠れ場所の口（洞窟、石のすき間、底の巣穴、草の株の根もと）に、マゼンタ #FF00FF の小さな丸を8個まで付ける | 丸の中心を隠れ場所にする。底の上の丸は burrow、ほかはすき間として、水槽の生き物が求める種類を割り当てる |

Codex の画像生成（編集）で、「琉球の川と河口」の3水景に作った。1水景2枚で約3分。頼むときの文面は、保管庫の `consumer/environment-requests-ja.md` の「地形の案内の絵」にある。作った案内の絵は、保管庫の `consumer/app-originals/environment/scene-<水槽id>/guide-occluders.png`・`guide-shelters.png` に置いた。

3水景（岩の多い渓流の淵、丸石と流木の川、開けた砂泥の河口）で、案内なしの下書きと比べた結果（道具を直す前）:

- **塗り分け版は効く。** 編集した絵は元の絵と構図がずれず、岩と流木だけを選んで塗れていた。案内なしの下書きは、3水景とも水草や根、水、手前の底まで遮蔽に巻き込み、小さな石を取りこぼしていた（2水景は単体テストに掛かる形）。案内ありは「どれを遮蔽にするか」をほぼそのまま採れた。
- **それでも手直しは要る。** 開けた河口（物体が3つ）は輪郭をそのまま使えたが、石の多い2水景は、石ごとの多角形に引き直した。理由は（このときの）道具の側にある。段を「手前から重ねた輪郭」にするので、隣り合う石が1枚にまとまり、石ごとに depth を変えられない。色の段は3つしかなく、手前の石どうしの前後は出ない。かすんだ奥の岩まで塗られると、絵の幅いっぱいの遮蔽になる。塗りの輪郭は絵の石よりなめらかで、少しずれる。
- **印の版は目安どまり。** 当たったのは 9個中2個、7個中2個、7個中2個。当たった丸は穴の口にほぼ正確に乗っていて、案内なしでは見つけられなかった洞窟の口と巣穴を見つけた。外れは、岩の表面、石どうしの境目、何もない砂の上。残す丸を人が選ぶ。
- **面は案内の絵では変わらない。** 面を歩く生き物（エビ・カニ）のための、段を分けて端点でつなぐこと、斜めの道、ガラスの縁からの余裕は、3水景とも手作業だった。面を歩く生き物だけの水槽では、乗せたくない石や流木の上面を消す判断も要る（下の `--no-tops`・`--connect-sand`）。

上の「手直しは要る」の理由のうち、石が1枚にまとまること、石ごとの depth、奥の岩の広い塗り、面のつなぎは、同じ日に道具を直した（次の2節）。

### 塗り分け版を物体ごとに分ける（2026年10月10日）

塗り分け版を渡したときの遮蔽の作り方を、「段ごとに手前から重ねた輪郭」から「塗られた物体1つずつ」に変えた。案内の絵を渡さないときの下書きは変えていない。97水景（上の評価のあとに足した5水景を含む）の `terrain.json`・`notes.txt` と評価の結果が、直す前と1バイトも違わない（直す前も後も、手前の線 76/97、砂の面 165/239、遮蔽の IoU 0.543・再現 0.845・適合 0.630、回避領域の IoU 0.274、隠れ場所 66/199、近い 26・手直し 39・大きく違う 32）。

1. **色の境目で分ける**: 赤・黄・青は別の物体にする。
2. **同じ色の中を分ける**: 案内の絵の大きさのまま分ける（作業用の大きさへ縮めると、石のあいだの細い線が消える）。塗りの中の細い輪郭線（塗りの色に近い薄い線も、まわりの色との差で拾う）と、絵の幅の0.3%までの細い切れ目を境目にする。線が途切れていても、くびれ（幅が、分かれる両側の細いほうの0.6倍より狭い所）で分ける。
3. **草の葉では分けない**: 塗りに掛かる草の葉などの切れ目（絵の幅の1.2%まで）は埋める。葉の後ろの岩は1つのまま。太さの変わらない流木や、枝の付け根でも分けない。
4. **小さなかけらは隣に付ける**: 見える範囲の0.4%より小さい物体は、同じ色で隣り合う物体に付ける。隣がなく0.2%より小さいものは捨てる。
5. **奥の段の広い塗りを外す**: 青の塗りのひと続きが、見える範囲の幅の20%以上（か面積の2%以上）あり、その6割以上が開けた水（奥行きの推定で、底でも物体でもない所）に掛かるなら、遮蔽にしない。`notes.txt` に出る。
6. **数の上限は16**: 超えたら、奥の段から順に、隣り合う同じ色の物体を小さいものからまとめる（まとめた幅は見える範囲の42%まで）。手書きでも、手前の石は1つずつ、奥の石はまとめて1枚にしてある。
7. **depth は物体ごと**: 物体の足もとの高さにある底の depth と、段の depth（0.3 / 0.42 / 0.55）の平均（0.1〜0.72）。回避領域の芯は、かたまりに入る遮蔽のうちいちばん奥の面（0.6 まで）の 0.15 奥に置く。

`--compare` を付けると、手書きとの近さの数字（遮蔽1つずつの対応、重ねた面積の IoU、depth の差）も出る。

手で直した地形と比べた結果（案内の絵つきの下書き。直す前 → 直した後）。「1つずつの対応」は、手書きの遮蔽ごとに、いちばん重なる下書きの遮蔽1つとの IoU が 0.5 以上あるものの数。「IoU」は遮蔽ぜんぶを1枚に重ねた面積で、石をまとめた下書きでも高く出る。「depth の差」は重なった所の平均。

| 水景 | 遮蔽の数（手書き / 下書き） | 1つずつの対応 | IoU | depth の差 |
|---|---|---|---|---|
| ryukyu-stream-gobies-90 | 12 / 5 → 16 | 2/12 → 10/12 | 0.588 → 0.588 | 0.212 → 0.060 |
| river-prawns-90 | 9 / 6 → 16 | 1/9 → 5/9 | 0.786 → 0.764 | 0.167 → 0.131 |
| estuary-mud-flat-150 | 3 / 3 → 8 | 3/3 → 2/3 | 1.000 → 0.874 | 0.198 → 0.031 |
| salmon-run-500 | 8 / 6 → 16 | 5/8 → 6/8 | 0.641 → 0.651 | 0.103 → 0.070 |
| spring-sticklebacks-60 | 12 / 6 → 15 | 1/12 → 11/12 | 0.698 → 0.715 | 0.091 → 0.072 |
| marsh-river-300 | 5 / 6 → 10 | 3/5 → 3/5 | 0.727 → 0.702 | 0.169 → 0.052 |
| 河口を除く5水景 | 46 / 29 → 73 | 12/46 → 35/46 | 0.688 → 0.684 | 0.148 → 0.077 |

数字を読むときの注意。

- 河口（estuary-mud-flat-150）の手書きの遮蔽は、直す前の道具の輪郭をそのまま採ったものなので、直す前が満点になる。直した後は、枝とカキ殻の塊、石ごとに分かれる。
- 重ねた面積の一致はほぼ変わらない（再現 0.814 → 0.835、適合 0.826 → 0.796）。変わったのは分かれ方と depth。下書きの遮蔽は手書きより多い（73 対 46）。塗られた物体をすべて出すので、要らないものを消す手直しになる。
- depth の決め方（底の depth と段の depth の平均）は、河口を除く5水景の手書きの遮蔽46個で、段の値だけ（差 0.138）、底の depth だけ（0.131）、近さの直線（0.088）と比べて選んだ（0.068）。選ぶのに使わなかった河口でも 0.198 → 0.031 になった。
- しきい値（くびれ 0.45〜0.75、輪郭線の差 10〜22、細い切れ目 0.2〜0.4%、上限 20）を1つずつ動かしても、1つずつの対応は 33〜37/46 で変わらない。上限を 12 にすると 23/46 に下がる（手前の石までまとめるため）。
- 下書きに差し替えた耐久テスト（`bun run test:tanks`）は、案内の絵つきの下書きでは流していない。

残っていること。

- 草の葉が絵の幅の1.2%より太く岩を横切ると、岩が葉の両側で2つに分かれる（marsh-river-300 の右奥の岩）。細い草（0.3%まで）が岩を完全に横切るときも分かれる。
- 途中で線に区切られた流木は、2〜3個に分かれる（river-prawns-90 の沈んだ枝）。
- かすんだ奥の岩が黄で塗られていると、遮蔽に残る（ryukyu-stream-gobies-90。手書きでは遮蔽にしていない）。外すのは青の広い塗りだけ。
- 輪郭線もくびれもなく重なった同じ色の石は、分けられない。

### 面を歩く生き物だけの水槽（2026年10月10日）

面を歩く生き物（エビ・カニなど）は、端点がぴったり重なる面にしか移れない。そのための選択肢を2つ足した。どちらも既定は切で、案内の絵がなくても使える。

| オプション | 中身 |
|---|---|
| `--no-tops` | 岩や流木の上面を面として出さない（砂の面とつながらない上面に乗った生き物は、そこから動けない）。寄り道先は出す |
| `--connect-sand` | 砂の面（手前・中・奥の段）のあいだに、物体を横切らない斜めの道（砂の面、3点）を渡し、道の付け根で段を切って、付け根がどの面でも端点になるようにする。道の横の長さは縦の3倍（絵の幅の8〜25%）を目安にし、付け根は段の面の上（もとの点か、点のあいだを約5%おきに刻んだ点）から選ぶ。面の端は、体長の半分とガラスの安全余白だけガラスから離す |

確かめたこと。

- 案内の絵のある6水景（案内あり・なしとも）で、砂の面がすべて端点でたどれるようになった（直す前は、段ごとにばらばら）。道は1水景に2本。
- 案内の絵なしで97水景に流すと、97水景とも砂の面がすべて端点でたどれた（うち2水景は面が1本だけ。道は合わせて173本）。
- 手で直した river-prawns-90 のように、流木や石の上面を道として砂の面につなぐことはしない。上面を残して（`--no-tops` なしで）つなぐのは手作業。
- 道が横切らないのは、物体のマスク（案内の絵があれば塗られた物体、なければ奥行きの推定の物体）だけ。確認画像で、道が石や草の上を通っていないか見る。段のあいだが物体でふさがっていれば、つなげなかった面の数が `notes.txt` に出る。

## 人が必ず見るべき点

1. `notes.txt` に出た注意。
2. 遮蔽が開けた水を覆っていないか。多角形は外側の輪郭だけなので、根のアーチや岩の穴のような「向こうが見える穴」は埋まる。穴の向こうを泳ぐ魚が消える。
3. 水草・海藻・根が遮蔽になっていないか。葉のすき間の水ごと魚を隠すので、手書きでは遮蔽にしていない。消すか、太い幹だけに絞る。
4. 遮蔽の depth。魚に手前を泳がせたい物体は奥（0.4〜0.5）、いつも魚の手前にある物体は手前（0.2〜0.3）へ。
5. 回避領域が泳ぐ場所をふさいでいないか、岩を素通りできる所が残っていないか。大型魚の水槽では特に見る。
6. 隠れ場所の種類と位置。住みかを持つ生き物（`homeShelter`）がいる水槽は、その種類が要る。
7. 水面より上まで見える絵。岸の面、水の外の巣穴、水面の高さ。
8. 直したら `bun run test:tanks -- -t <水槽id>` と `bun run test:fast`。

## うまくいかなかったこと、試してやめたこと

- **底を1枚の平面として当てる**: 最初は「視差が下へ一定の割合で増える平面」を RANSAC で当てた。手前が急に近づく谷のような底（lamprey-90）や、見える範囲に底が少ししか映らない水景（tanganyika-rocks-180）で、手前の砂利が丸ごと物体になった。行ごとの底の視差に替えると、この2水景の底が取れ、全体でも砂の面の一致が 65% 前後から 71% へ、遮蔽の IoU が 0.49 から 0.51 へ上がった。
- **色ときめだけで水と物を分ける（奥行き推定なし）**: 水の色（行ごとの中央値）との差ときめで水を切り、底の色で底を切る方法を試した。遮蔽の IoU は 0.26、再現 0.94、適合 0.27 で、見える範囲の 56% を遮蔽にした。遠くの岩や光の筋を手前の物と区別できない。きめは、奥行き推定の読み違い（開けた水）を落とす役にだけ残した。
- **SAM で輪郭を取り直す**: 下書きの遮蔽を、箱と点を付けて SAM（`facebook/sam-vit-base`）に渡した。20水景で、手書きとの IoU は 0.582 から 0.573 で変わらなかった（岩の水景は +0.03〜0.05、水草の水景は下がる）。1水景あたり約2秒かかる。採らなかった。
- **Depth Anything V2 Base**: 遮蔽の IoU 0.522（Small は 0.514、同じ条件で比べたとき）、手前の線は 74%（Small は 77%）。差がなく、Base は CC-BY-NC-4.0 なので Small を既定にした。`--model base` で試せる。
- **回避領域を底とガラスまで伸ばす**: 上の「下書きで動くか」のとおり、かえって落ちた。
- **根の林立する水景（mangrove-180）**: 細い根を落とす処理と、すき間を埋める処理がぶつかり、根の間の水ごと1枚の遮蔽になる。直せていない。
- **水草が画面を埋める接写（pea-puffer-30、macro-fresh-30）**: 両側の草むら全体が遮蔽と回避領域になる。手書きは石だけを遮蔽にしている。何を物体として扱うかは、絵からは決められない。
- **小さな石（sand-flats-180）**: 見える範囲の 0.4% より小さい物体は落とすので、砂地に転がる石は出ない。
- **奥行き推定の読み違い**: 開けた水を手前と読む（深海の大水槽、黒潮の大水槽）、水面の裏の映り込みを手前と読む（マングローブ）。きめと近さの下限で落としているが、きめのある水面の模様は残ることがある。

## 画像を作る側に頼むとよいこと

試した結果から、効きそうな順に書く。水景の絵と同じ大きさ・同じ構図の画像か、文字の一覧で受け取る想定。1と2は、2026年10月10日に Codex の画像生成で試した（上の「案内の絵を使う」）。

1. **遮蔽にする物体のマスク**: 魚が後ろに隠れる物（岩、太い流木、サンゴの塊）を単色で塗った版。物体ごとに色を変え、できれば手前・中・奥の3段を色で分ける。水草・海藻・細い根は塗らない。下書きの弱点は「どの物体を選ぶか」（適合 0.6）と「穴のある物体」で、輪郭そのものではないので、選んだ結果をもらうのがいちばん効く。展示室の絵でガラスを緑（#00FF00）に塗ってもらっているのと同じやり方にできる。作り直した版は絵と画素がずれることがあるので、受け取ったマスクを奥行きから出した物体のマスクと突き合わせて、ずれを自動で確かめる仕組みを足すとよい。まず3〜5水景で試す。
2. **隠れ場所になる所の一覧**: 巣穴、イソギンチャク、海草の株、洞窟の口、岩の割れ目の位置。絵に印を付けた版か、「左下の岩の下に洞窟」のような言葉でもよい。巣穴・イソギンチャク・海草は絵から決められず、洞窟の口も下書きは見つけていない。水槽に入れる生き物の住みか（展示計画の種）に合わせて描いてもらうと、絵と地形が食い違わない。
3. **水面の高さ**: 水面より上まで描いた絵は、手前と奥の水面の高さ（`waterLine` の front と back）。岸に上がれる所があれば、その範囲。
4. **構図の条件**: 見える範囲（ガラスの縦横比で切った中央の帯）の下端に、底が横に長く見えていること（手前の面を置く場所になる）。魚を隠したい物体は、輪郭のはっきりした塊にすること。根や茎の林を遮蔽にしたいなら、すき間の少ない太い幹を手前に置くこと。
5. **底のマスク、奥行きの地図は頼まなくてよい**: 砂の面は絵からの推定で足りている（手前の線は77%）。奥行きは Depth Anything V2 の推定で足り、画像生成で別に作った奥行きの地図は絵と食い違うおそれがある。

前景を別のレイヤー（透過 PNG）で納品してもらう方法は、遮蔽がそのまま決まるので最も確かだが、「完成した一枚絵」という今の決まりと、レイヤーどうしの画素の一致が要る。1のマスクで足りるかを先に確かめる。
